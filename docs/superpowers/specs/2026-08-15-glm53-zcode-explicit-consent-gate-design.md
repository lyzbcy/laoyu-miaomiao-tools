# GLM-5.3 ZCode Skill 明确同意门控设计

## 目标

防止 `lyzbcy-glm53-zcode-eval` 被 AI 自动启用。该评测配置可能让通用任务的回答更保守、执行方式更受约束，出现用户所说的“降智”体验，因此默认必须关闭。

## 唯一调用条件

只有当前用户消息把下面这句话作为明确的启用指令时，才允许执行 Skill：

```text
请使用 LYZBCY 虚拟环境测试
```

仅讨论、引用或介绍这句话不算授权；AI 自己复述这句话不算授权；其他近义表达、Skill 名称、`$lyzbcy-glm53-zcode-eval` 或以前任务中的授权也不算授权。授权只适用于当前任务，不自动延续到新任务。

## 三层门控

1. `agents/openai.yaml` 设置 `policy.allow_implicit_invocation: false`，禁止平台隐式注入。
2. `SKILL.md` 的 description 只声明精确口令触发条件；正文开头设置硬门槛。缺少有效口令时，不读取提示词、不运行测试、不运行安装器、不修改配置，只能询问用户。
3. `README.md`、`docs/index.html`、网页 AI 摘要和 Release 说明统一展示默认关闭、潜在表现影响、唯一口令与询问机制。

## 询问机制

如果 AI 判断这项评测可能有帮助，先说明它可能让当前任务表现更保守或不灵活，再询问用户是否启用，并要求用户明确回复唯一口令。在收到有效回复前继续使用普通模式，不能先执行再补问。

聚合仓库发布 `v1.5.1`，资产名继续使用 `lyzbcy-glm53-zcode-eval.zip`。网页和 README 的固定下载链接从 `v1.5.0` 更新为 `v1.5.1`，旧 Release 保留供审计。
