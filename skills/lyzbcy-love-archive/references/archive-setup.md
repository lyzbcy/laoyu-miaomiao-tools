# 恋爱关系档案 · 搭建与维护

> 目标：把两个人之间发生的点点滴滴分类存下来，让未来的你们（和 AI 助手）随时翻回去。

## 为什么值得做

时间久了，一顿饭、一次拌嘴、一个默契瞬间会越积越散。人的记忆不可靠，
细节会模糊，情绪会淡。档案的价值不是怀旧，是**让下次决策有据可查**：
送礼物不踩雷、吵架不翻旧账糊涂账、纪念日不遗漏。

## 目录结构（推荐起步模板）

```
doc/
├── 初心与使命.md      ← 北极星：为什么建档案、红线是什么
├── TA的基础信息.md     ← 生日、尺码、共同爱好（按需增减）
├── 饮食与饮品偏好.md   ← 口味、忌口、常点的店
├── 礼物与约会灵感.md   ← 送过的、想送的、想去的地方
├── 02-吵架与沟通.md    ← 复盘记录 + 沟通方法论
├── 03-旅行记录.md
├── 04-情书与表达.md
├── 05-异地恋心得.md    （非异地可删）
├── 07-纪念日与生日.md
├── 08-性格与观念冲突.md ← 双列分析：你的特点 + TA 的特点 + 重大观念差异
└── 09-关系时间线.md    ← 从认识到现在的里程碑
```

## 维护原则

1. **真实优先**——记录真事，不文学创作。不美化、不杜撰。
2. **分门别类是核心价值**——新事实优先追加到现有分类；检索不到的档案等于没有。
3. **渐进式披露**——顶层只放索引和概要，细节按需展开；条目带日期，保留原始日期。
4. **标注不确定性**——"待确认""持续时间不知道""推测原因"就照实写。
5. **为未来服务**——格式要让"半年后的你"和"换了新模型的 AI"都读懂。
   条目量大到 markdown 难维护时，可迁 JSON/SQLite，但读取入口保持 AI 友好。
6. **红线**——档案默认私密；任何对外暴露（发帖、分享）前必须经本人同意。

## 从聊天记录批量建档（进阶）

如果有导出的聊天记录（如微信），可以按这个思路蒸馏进档案：

- **统计层**：总量/双方对比/月度趋势/活跃天数——适合做纪念日惊喜（年度报告）；
- **事实层**：从对话里挖偏好（口味、口头禅、愿望清单）→ 归入对应分类文件；
- **方法论层**：吵架场景的上下文挖掘（对方说"哄"时前后 20 条）→ 提炼成你们自己的
  「哄人规格书」，注明日期和原话出处，事后只追加不覆盖。

注意：聊天原文比档案更私密，解密/导出的数据不要进 git、不要上传网盘。
