# 统一收尾与经验贡献

本页适用于独立投稿，或接续 `software-video-production` 的制作与发布任务；单独安装本skill也应能完成收尾，不依赖另一个skill文件存在。本页不改变提交、账号、公开范围、防重和特殊平台授权门禁。

## 接手续做，同一作品只汇总一次

用户说“可以了，去全平台发布吧”等采用成片并继续发布的指令时，沿用当前项目、已采用视频/封面/文案的路径和指纹、用户反馈与版本记录、验收范围、平台范围及待办。若平台范围已约定则沿用，不重复索取已给授权；“全平台”不自动包含未选平台。视频号逐片确认、公众号群发单独授权等原门禁仍生效。当前只是维护/讨论skill时不执行真实投稿。

制作与发布共用项目 `run-summary.md`：有制作段时读入保留，只补发布段；没有制作记录时只总结已知投稿过程，制作历史标未知，不从v12文件名推断12次制作。不复制视频工程到另一个大目录。记录视频指纹、`closeout_owner: publisher`、`closeout_status: pending/partial/complete`、`summary_sent`，以及清理/贡献邀约与答复；用来跨轮恢复和避免重复，不自动创建调度或跨聊天发消息。

完成当次授权目标后，最后阶段发送一条合并消息：

1. 最终成片、封面与制作改版简述（已知时）。
2. 用户反馈与AI碰壁：制作/发布分开，用户反馈与Agent自检分开；实际修复、重试、换稿次数有据可查。页面重读、上传等待、confirm查询不充作新版本；未知就写未知。
3. 每个平台的本次账号、授权目标、实际状态、作品/稿件ID、可给出的链接及待办。账号与私有稿件细节只留项目，外部分享需脱敏。
4. 最后如何完成：用了什么脚本/平台适配、何种修复、如何续跑和防止重复发布、做过什么验证及未知；不堆工具名称。
5. 制作和发布经验各自的贡献价值；必要时附一次清理提醒和一次PR邀请，两项分别同意。

草稿、上传受理、已提交、审核中、平台内已发布和外部公开分别报告。黄灯/审核/结果不明先做有界查询，不重传重发、不无限等待。仍未达到授权目标时发送合并阶段回执，`closeout_status`记partial，保留恢复待办，不宣称“全平台发布完成”；目标完成，或用户明确结束本轮并接受待办后，再最终收尾。仅授权保存草稿时，草稿核验完成即可按该目标收尾，不追加公开投稿。

制作段已写总结时不照抄两份；已经发过清理/贡献邀请或收到答复时直接沿用，不因换skill再问。已交付后后来续发其他平台，就在同一记录追加本次平台结果，说明新增部分；用户改变成片后按新指纹建立新稿，不能复用旧提交授权。

## 哪些发布经验值得贡献

| 情况 | 可贡献的内容与证据 |
| --- | --- |
| 接入新平台 | 平台适配、字段/账号核验、封面与声明处理、草稿重开、稿件唯一定位、提交与终态/防重；标清已验证步骤和仍实验的步骤，不把登录或一次上传当全链支持 |
| AI反复碰壁 | 问题触发条件、最小复现、错误假设与根因、修复前后行为、可复用的停止/恢复判断；例如同名话题歧义、SPA路由竞态、按钮作用域和错误成功信号 |
| 脚本更稳定 | 以重复上传风险、定位唯一性、等待/恢复、幂等和兼容性等可观察行为说明改进；保留离线fixture/失败样例/回归结果，不仅说“更稳定了” |

先对照已有规则和适配；已覆盖的普通操作、一次临时网络失败、手动过一次验证码、账号特定数据通常只留项目。没验证的方案标待验证，负面案例说明失败条件也可有价值。为贡献而重复真实投稿、绕过平台验证或削弱授权门禁不可取。

## 草案、同意、PR与贡献者

值得时先在本次专属 `.contribution-tmp/<run-id>/contribution-draft.md` 保存草案，列问题/适用条件、复现与最终方案、实际验证/未知、目标文件及候选差异。新平台代码同时准备明确的支持状态与回归样例；仅文档经验不强制开发脚本。普通投稿只准备项目内候选，不自动改已安装的共享skill；已获明确维护授权时按其范围执行。

草案去掉账号、cookies/token、私有稿件URL、个人身份、用户视频/封面和整段真实DOM/聊天记录；合成fixture只留复现必需结构，授权与稿件指纹也不当公共账号证据。不自动公开材料。用户确认最终交付或本轮任务结束后，在合并消息中（小结已发则单独补邀约）具体询问一次：

> 本次“……平台接入/……碰壁修复”有复用价值，已整理脱敏草案（链接），拟改……，已验证……，仍未知……。你愿意把它作为PR贡献给发布skill吗？审核合入后可按确认的名字或GitHub账号加入贡献者名单，也可匿名。尚未提交，拒绝不影响交付。

没有值得沉淀的经验就简述原因，不机械邀约。拒绝、不答复、仅说发布成功都不等于贡献同意，不反复催问。若制作经验也值得贡献，合并成一份分明标注两个skill改动范围的草案，只问一次；同意其中一部分只提交那部分。

目标仓库：[lyzbcy/laoyu-miaomiao-tools](https://github.com/lyzbcy/laoyu-miaomiao-tools)，发布skill目录 `skills/lyzbcy-video-publish-assistant/`。用户同意范围与署名后，在其可用账号/fork或有权限的贡献分支提交PR；不直接推主分支或自动合并。代码按随包[回归要求](regression.md)检查，文档检查链接和打包清单，描述根因、最终行为、验证与边界。不要拿发布授权当作提交PR的授权。

PR同时修改本skill的 `CONTRIBUTORS.md`，本人确认名字/账号或匿名，同一人合并一条，关联实际贡献与PR；仅有制作贡献就只在制作skill登记，两个skill都受益才分别登记。维护者合入时核对名单，合入后正式随skill分发；提出邀请、用户同意、提交PR和合入署名分别报告，不提前声称入选。环境要求时将实际PR链接附加到当前聊天。没有账号/权限/网络就交付补丁和PR正文，明确尚未提交，不假报链接。

## 存储清理：统一提醒，保住恢复能力

最终收尾时盘点本项目旧版本、预览和可重建缓存的真实大小；共用制作阶段 `cleanup-plan.md`，不重复扫描或开第二份清理方案。至少3个被替代的评审版本或候选约2GiB时默认主动提醒，用户阈值/单个大文件/磁盘紧张可调整。列候选绝对路径、测量大小、保留项与预计可释放空间；不知道大小就写未知，版本数与文件数分开，不按“每版1G”推算。

保留最终视频、平台必要派生视频/封面/文案、源素材、最终工程/脚本/配置、运行小结和关键验证；还要保留投稿manifest、授权/指纹、防重账本、attempted记录、作品ID和恢复断点。待上传、审核/失败可能续跑或用户仍在改稿时，相关文件不列候选。不扫其他项目或共享依赖、不整目录按v1/v2名字删除。

先交付一条有清单和预计空间的提醒，再按用户明确同意的范围清理；未同意不删，已同意不重复问。清理与PR是独立选择。同意后解析并验证绝对路径在批准范围，复查引用，操作后核对最终交付及恢复记录可用，报告实际处理和实际释放空间；回收站/同盘归档不冒充已经释放。同步目录删除会传播，清单中说明，保护运行任务与其他项目。


## 跨skill去重与最终确认

多个skill串联时共用同一项目、运行ID与 `run-summary.md`，只由 `closeout_owner` 所指的最后阶段发送完整收尾；前序skill只补记录。共享记录增加 `final_delivery_confirmed`、`contribution_invitation_status`（not_offered/offered/accepted/declined）、`contribution_scope`、`contribution_temp_paths`、`contribution_cleanup_status`（not_created/pending/cleaned/failed）与提交结果。已收到的答复、已清理状态沿用，不因换skill重建贡献包、重复邀约或重复提醒。

`summary_sent` 仅表示完整最终小结已发送；partial阶段回执不能置为true，以免吞掉后续最终收尾。投稿仍有待办时给合并阶段回执；目标完成或用户接受待办结束本轮后，最后阶段才发送一次完整小结。发送后及时登记状态。恢复时先读记录；发送是否成功不明时先核实，不直接重发。

PR邀请必须等用户确认最终交付/本轮任务结束，不能把文件生成、上传完成或制作通过视为整个发布任务已获确认。“可以了，去全平台发布吧”只确认制作并延伸任务，等发布收尾获确认再邀请。若最终小结已发送但用户尚未确认，先不邀请；确认后可单独补一次简短邀请，不重发整份小结。用户随后对贡献或清理的答复需要处理并回报结果，这类简短执行回执不算第二次完整收尾。

## 用户答复后的临时贡献包清理

本节落实“集思广益提pr”组件。制作与发布共用本次专属 `.contribution-tmp/<run-id>/` 和创建清单，草案为其中的 `contribution-draft.md`；不各建一包。只准备脱敏短文本及必要候选差异，不复制视频、源素材或整个工程。运行记录保存目录绝对路径和自己创建的文件清单；正式交付不能放进临时目录。

- 用户拒绝：记录不提交，清理本次临时贡献草案、包和打包缓存，停止邀请。
- 用户同意：先完成获准范围的PR或补丁交付，记录PR链接/补丁交付及署名意愿，再清理临时包与一次性副本；不得先删除唯一待提交补丁。只同意其中一个skill，就只提交该范围，其余临时候选也在处理完答复后清理。正式贡献者以审核合入为准。
- 提交失败：如实记录未提交和失败原因，将最小可用文字补丁保存在项目运行记录或正式补丁交付中，再清理大包和打包缓存；用户明确要求保留的按其要求处理。
- 用户未答复：不提交、不把沉默当同意或拒绝，不反复催问；无需一直等待，避免生成或持有大包，后续收到答复按上述分支处理。只答复旧版本清理不代表答复了贡献邀请，两个选择分别登记。

这类由本次贡献流程创建的临时文件，答复后清理属于组件收尾，不再要求第二次清理授权。执行前解析并核对绝对路径属于本次专属目录，按创建清单处理，不跟随链接或删除目录外内容；同步目录删除会传播。保留最终交付、源素材、既有仓库与依赖、账号凭据、运行小结、PR链接及必要提交结果。清理失败记failed与残留路径，不能声称已清理。记录完成后只简短回报“已提交/未提交，临时贡献包已清理”；没有创建包就写无需清理。

**旧视频版本清理是另一件事**：仍按 `cleanup-plan.md` 的具体范围取得用户同意；同意贡献不授权删旧片，同意删旧片不授权提交PR。上面自动清理的范围仅限本次自建临时贡献文件。

## 持久化收尾检查

同一项目的制作和发布共用一份closeout.json。制作workflow初始化时即创建，发布接续只恢复，不重置。每次恢复先status，准备结束前audit：

```powershell
python scripts/closeout.py init LEDGER
python scripts/closeout.py status LEDGER
python scripts/closeout.py record LEDGER --task experience_review --status valuable --evidence ASSESSMENT.md
python scripts/closeout.py record LEDGER --task contribution --status approved --evidence USER_CONSENT.json
python scripts/closeout.py record LEDGER --task contribution --status submitted --evidence PR_RECEIPT.json --url https://github.com/OWNER/REPO/pull/NUMBER
python scripts/closeout.py audit LEDGER
```

init只在新运行首次执行；已有账本再次init会拒绝，不覆盖决策。status返回紧凑未决项；audit有未决或证据变化时非零退出。任务包含交付确认、经验评估、贡献、归档、旧片清理和临时贡献包清理。经验无复用价值可明确not_valuable后not_needed；用户拒绝记declined；已有明确授权沿用，不重复邀约。投稿或合集审核待办与可执行收尾项分别记录，不能因一个partial吞掉其余收尾检查，也不为越过最终确认时机提前邀约。

归档verified使用JSON索引的files数组，每项path和sha256须对应真实保留文件；就地索引、打包和物理迁移分别报告，不把索引称为已搬走工作区。清理cleaned的JSON回执含deleted路径数组，脚本核对这些路径确已不存在；awaiting_consent不能算已清理。retained只用于用户明确决定保留，不能把未回答改成保留授权。PR submitted必须保留单独的用户授权证据及实际PR链接。归档或清理的实质操作仍由当前授权范围决定，脚本不自动发PR、删文件、催用户或创建后台调度。

新任务在项目入口记录固定恢复与收尾命令，使下一次从磁盘定位，而非仅依赖聊天摘要。账本不是后台自动执行器；若Agent不调用入口，仍可能漏，因此SKILL入口与交付步骤都显式路由到status/audit。贡献授权、PR提交、合入和正式发行仍分开，不能因门禁通过就宣称已合入。
