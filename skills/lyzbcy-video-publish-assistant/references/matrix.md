# 内容矩阵、发布终态与接口试点

## 一条内容对应多个平台稿件

manifest 可加 `content_id`、`content_title`、`series`，平台段可加 `account_label` 和 `publication_id`（同内容在同平台的多个账号/稿件必须明确区分，默认ID为content_id:platform）。确认器成功时自动生成运行目录下的 `publication-registry.json`，包含内容、平台、原生ID、状态、合集/活动。查询失败不生成成功记录；submitted不能覆盖published；缺少ID、公开URL或精确发布时间时留空，不用本机时间补成发布时间。

看板导入该文件后按显式稿件身份采样。不能用相似标题推断同一内容，不能将上传成功视为公开可见。此文件不包含浏览器凭据或整屏DOM。实际账户仍按投稿UI回读，account_label是登记信息，不能替代身份核验。

## 终态回读

小红书切换已发布筛选后，等待对应标题卡片真正出现再读；只查询，不重复发布。分钟时间戳与提交同一分钟且没有绑定noteId时继续黄灯。新版YouTube“视频发布时间 / 上传于 / 分享链接”须同时匹配已授权尝试、精确标题及本条视频ID；另一条公开作品不能作为成功证据。

## 官方接口试点

`scripts/youtube_api.py` 实现官方YouTube可恢复上传，默认只有本地preflight；加 `--execute-private-upload` 才建立私有视频。它不做公开发布，不自动替代现有发布器。需要已授权OAuth access token，同时满足上传及读取当前频道身份的scope（youtube.upload + youtube.readonly，或等价更完整授权）；网页登录态和账号密码都不能冒充OAuth token。

```
python scripts/youtube_api.py VIDEO --title TITLE --channel-id CHANNEL_ID --state PRIVATE_LOCAL_STATE
```

token仅从 `YOUTUBE_ACCESS_TOKEN` 环境变量取，不写日志或状态文件。session URL带恢复权限，状态文件放私有缓存，不进公开仓库。当前频道须与指定频道唯一匹配；每次恢复先探测服务端已接收位置。结果不明不创建第二个会话，文件/标题/频道变化不复用。公开范围、活动、合集、封面和最终提交仍经原有UI及授权门禁；不能因为HTTP成功就略过。

本轮完成离线协议与中断恢复测试，未用真实素材做重复投稿；未取得OAuth授权前状态为“未接通实账号”。B站、抖音、小红书、视频号未试验的内部接口不填写可用；按实际请求契约验证后再扩展，优先查询和草稿，保留UI回退。

官方依据：https://developers.google.com/youtube/data/guides/using_resumable_upload_protocol

## 多期补齐与系列运营

用户要求检查前几期并补发时，先建立“明确期号×本次平台”矩阵，锁定每期采用母版与哈希；从既有发布回执找原生ID，再按当前作品/账号核对现状。已有作品只补合集、活动等缺口；列表暂未出现、相似标题或旧稿状态不能直接判缺失并重传。查不到时继续核对标题、ID、视频时长和草稿，发布结果不明只查询。各平台状态独立，不因另一个平台成功而打勾。

沿用已确认的系列名称；创建合集前查同名对象，逐期核对关联和期序。保存重开后看具体三期/多期标题或ID，不能用合集存在、总数增加或本次新片入集代替历史各期入集。平台没有当前账号可用的合集能力时，记录实际入口/资格限制，不冒充已入集，也不另建无关私密书签当公开合集。

“合适活动参加”包括投稿前查当前有效候选、内容方向和参与条件，选中后回读；对已发布旧片，检查平台是否允许补报，原已合适参与的保留。检索到活动名、填普通话题、后台推荐词不等于参加成功。B站每条最多一个活动，避免为凑活动选不相关主题；支付、商业履约或新合约要求不从普通发布授权推导。未适配平台继续人工UI路线并如实记录边界。公众号发表与群发分开，用户仅要求发布时默认不群发。
