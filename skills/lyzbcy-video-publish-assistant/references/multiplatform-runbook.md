# 多平台运行手册与提速

并行安排本地准备和平台等待。浏览器内同一 session 的表单和弹窗串行操作，处理完当前弹窗再切平台。配置、提交及断点恢复见[执行命令](automation.md)。

## 平台差异

|平台|本轮可复用的处理|保留的边界|
|---|---|---|
|抖音、B站、小红书、YouTube|沿用四平台CLI；按合集/活动/声明各自读回|完成终态后不重复打开上传页|
|X|原生视频Ready与AI标识；公开正文还原img表情alt后全文匹配|自定义封面以实际入口为准；草稿恢复异常按既有扩展手册收敛|
|视频号|实际Shadow DOM视频input；封面先进入“直接编辑/使用素材”后的实际编辑器，再选图、保存、重开；AI标注提交前复核|仍为参数化上传＋现场UI步骤，不是完整CLI适配；原创声明按本片素材与平台条件单独核对|
|公众号|与知乎、掘金共用正文；先发视频号，再插入该条原生组件，保存重开比对nonce/描述；封面、摘要、AI来源单独核验|只发表与群发分开；原生组件可见不等于手机完整播放已验收|
|知乎|从真正“导入文档”菜单选MD；上传原生视频和封面；重开后再查AI声明；发表页核验|同样支持MD的知识库附件input不是文档导入，按父级功能限定控件|
|掘金|同源正文转排版，保存重开；发表后检查实际外链href，尤其含下划线的视频ID|本轮用播放链接替代，不能声称原生视频已嵌入|
|快手、微博|原生上传、实际AI声明、公开范围、单次提交；在已发布列表/本人主页按当前条取原生ID|本轮仍是现场UI实验路径，不宣称所有账号或完整CLI已支持|

标题标点限制按当前平台报错适配，保留题意；不要因此改动已经采用的母版。活动只选择本账号本次可见且匹配内容的候选，没有合适项如实记录。

## 公众号扫码、审核和窗口恢复

- 视频号创作中心的登录入口出现「快捷登录」时，先尝试恢复同账号会话；进入后核对创作中心昵称及投稿页。一次投稿中由用户点按快捷登录恢复了同一账号会话，随后发表并从作品管理和公众号原生选择器读回。公众号文章的发表验证由后台单独触发。

- 登录扫码与本次文章发表验证是两步，不能把登录成功写成文章已通过验证。管理员/运营者需要扫码时，把同一草稿验证窗口留给用户；不绕过，不提前说“已发表”。
- 本期已发布视频号时，公众号通过原生视频号选择器引用该条。两个账号未绑定时，搜索视频号完整昵称，打开动态列表，按本期完整描述定位唯一结果，确认已选一条再插入。动态尚未出现时保持草稿并等待同一条作品。扫码预览、发表验证与群发通知分别核验。
- 每次重新打开发表弹窗都重新读取群发开关，确认页面显示“未开启群发通知”后才继续，并保留该证明。“默认关闭”是本 skill 的约定，不是页面默认值：2026-11-23 实测该开关的页面默认值是开启，只发表时必须先关再点，发表后在状态详情里读「已通知 N 人」。弹窗开着的时候不要交给用户点击，那次就是这样带着通知提交的。
- 另有群发授权时绑定本篇账号、正文/封面指纹及引用动态，不复用到后续文章。原创/自制与AI标识分别按平台和素材条件核验，保存重开确认；已发稿只修改原稿，不为补声明删除重发。
- 用户明确说已关闭并要求重新打开时，先读本次发表记录。已经发表只补结果；仍是同ID草稿且未发表时，按该次明确恢复指示重开验证，保留原attempt和此次重开事件，不清空账本。不因超时或无回复自行重开提交。
- 用户说扫好了，先查当前记录：审核中继续有界查询，已发表再取得永久公众链接并核对本期原生视频；临时tempkey地址不当永久链接交付。可以使用`wechat-confirm`只读确认。
- 扫码后可刷新已登录的公众号首页，从「近期发表」读本条状态和公开链接。公众号会在 AI 等英文前后渲染不换行空格，按 Unicode 空白折叠后比完整标题，并结合账号与发表时间。
- 已关闭的tabId会失效。先列现有标签；如同session全部业务标签已被用户关闭，选一个可访问的现有网页作连接锚点再新开本任务页，不改其内容。edge://标签不可接管，连接正常时不重启浏览器或daemon。

需要衡量耗时时，分别记录主动操作、平台等待、实际重试及失败原因。维护见[回归与本地同步](regression.md)。

## 活动投稿后的指定转发

有明确本期授权及指定联系人或群时，将原生视频发布、作品卡片分享、附言或群打卡分别记录。以本期原生作品 ID 找到实际分享入口，逐项核对会话全名及类型。给个人的“已发布”通知与群里的“打卡”按用户要求分别发送，逐会话回读；一项已成功时只补另一项。作品卡片用抖音原生分享完成。公开视频页或后台已受理各自对应不同回执，不能用粘贴直链来代替已要求的原生转发。

2026-11-20 实测补充。播放页快捷分享只列部分近期对象。目标未列出时，先在已收到本期卡片的授权会话回读作品，打开该卡片的右键「分享」，进入「选择朋友」完整列表，再按唯一会话名发送。弹窗「已发送」之后回到目标会话，分别核对原生卡片和附言。桌面网页会话列表可能仍存在于 DOM，但被聊天页遮住。先点当前会话左上返回按钮，重新核对可见行和新会话标题，再发文字。群名显示的排版空格可归一。

抖音活动话题建议无候选时，在正文末尾分两次输入空格加井号和主题词，等待唯一原生候选再选取，用话题元素及保存重开结果核验。封面编辑器可能从竖版打开，读取实际预览比例后上传对应图片，再切换另一比例；分别核对缩略裁切。

部分恢复观察：Kimi daemon 在线但扩展掉线时，打开原 Edge 个人资料及现有扩展侧栏曾让 `extension_connected` 短暂恢复；导航或附着仍需要独立读回。没有可操作的标签页时，在本地先完成稿件和指纹；不得将连接状态报作已进入投稿页，超时后也不得重复盲点提交。

## 2026-11-23 实测补充（Windows、Kimi Browser Extension 2.0.37、Edge 151）

单账号一轮六项投稿的观察。标「本次」的只有一次样本，换账号或换版本要重新确认。

桥接超时先分类。用只读 `evaluate` 取 `performance.now()` 连续计时。窗口最小化或被其他窗口完全盖住时每次 3 到 12 秒或超时；目标不是所在窗口的当前标签页时同样超时；扩展掉线时报 `extension disconnected`，本次约 30 秒后自动重连。前台窗口的当前标签页稳定在 0.0 秒，作为基线。

不抢焦点地保持可见。用 `msedge.exe --profile-directory=<配置目录> --new-window about:blank` 另开同登录态窗口，`SetWindowPos` 置顶并移到屏幕边缘，只留约 10 像素可见，全程不激活。只在这个窗口里用同一个标签页顺序导航：扩展新建的标签页是后台标签，2.0.37 的 `Page.bringToFront` 只开启焦点模拟，不切换当前标签。扩展重连后重新 `attach_tab`，页面内容不丢；恢复后的任何提交前先查管理页。结束时关闭焦点模拟、`close_session`、取消置顶，并把主窗口恢复原状。

视频号。短标题不接受逗号，页面提示可用空格代替。描述里用真实按键输入井号、话题文字和空格，直接生成 `span[data-type=topic]`，本次没有候选弹层。封面上传的 input 在 `wujie-app` 的 shadowRoot 里，按 `accept^=image` 取并用 `DOM.setFileInputFiles` 写入；本次点「编辑」直接进入 9:16 裁切框，没有出现「直接编辑/使用素材」选择。接口返回 `errCode 300334` 时页面提示「账号已在其他设备登录」，本次对应的是网页会话被挤下线；先存草稿，`post/post_draft` 返回 `objectId`，重新登录后从草稿箱重开，字段完整保留。草稿箱行的编辑图标在悬停后出现在行右侧，删除图标紧邻其右，点击前排除 `.weui-icon-outlined-delete`。发表成功的依据是 `post_create` 返回成功、toast「已发表」并跳回列表。

公众号。新版编辑器地址是 `appmsg?t=media/appmsg_edit_v2&action=edit&isNew=1&type=77`，可以临时包装 `window.open` 取得地址而不新开标签。标题和正文都是 `div.ProseMirror`；正文结构用带 `text/html` 的合成 `paste` 事件一次写入。图片占位段被选中时，对编辑器的 `input[type=file][accept^=image]` 设文件即原位替换成上传后的图片。「视频号」入口先选最近使用里的账号，再按完整描述唯一定位卡片；组件的 `data-nickname`、`data-desc`、`data-nonceid`、`data-id` 用于保存后重开和公开页两处核对。封面走「从图片库选择」，对话框内的文件 input 设文件后自动选中，再分别裁 2.35:1 和 1:1。**本次发表弹窗里「群发通知」开关的页面默认值是开启**，与上文「默认关闭」的约定相反：只发表时必须先关再点，发表后在状态详情里读「已通知 N 人」。弹窗停留期间不要让人接手点击，本次就是这样被带着通知提交的。

小红书图文。页头 `.header-tabs .creator-tab` 有离屏和透明克隆，取屏内、`opacity` 大于 0.5、无 `aria-hidden` 的那个。图片 input 为 `input.upload-input[accept^='.jpg']`，支持多选。`confirm_published` 的时长校验不适用于图文，用 `terminal_review` 记录终态。公开直链显示「当前笔记暂时无法浏览」时，以笔记管理的「已发布」筛选为准，站外访问单独记为未验证。

抖音图文。入口是页签「发布图文」，图片 input 为 `input[type=file][accept^='image']`，标题 input 的占位是「添加作品标题」。标题和正文之间的句号由平台拼接。`submit` 后 25 秒内没读到成功提示但已跳到 manage 路由时，刷新管理页核验。管理页搜索框会触发 `openapi/aweme/v1/home/search/item`，响应里的 `aweme_id`、`status`、`risk_infos` 可用来取原生 ID 和核对声明标记。`shoot_way` 与 `misc_info.activity_feed_json` 本次在一条活动入口发布的作品上有值、在两条网页发布的作品上为空，推测可以用来区分入口，样本太少，待复验。

声明策略。**默认如实声明**：成片含合成旁白、生成封面或画面、合成动效时，抖音选「内容由AI生成」，小红书选「笔记含AI合成内容」，视频与图文两条投稿各设各的。作者明确要求不声明时，先把下面的实测回读给作者；作者仍坚持才按作者的决定执行，并在授权文件里写明依据。实测（2026-11-25，样本各 1，不代平台规则）：一期投稿的小红书视频与图文未声明，作者从小红书通知得知笔记被平台检测出 AI 生成后限流，视频观看 1、图文 0；抖音上带「作者声明」标记的往期作品正常分发，同片未声明的抖音作品当时也未见限制，当天补声明后状态与互动数未变。

公众号快捷登录。Edge 151 里 `navigator.permissions.query({name:'local-network-access'})` 为 `prompt` 时，本次页面只剩二维码，推测快捷登录框架因此探测不到本机微信，没有做对照验证。`Browser.grantPermissions` 不在扩展的 CDP 透传里，这一步本次由用户在浏览器里登录。

文档回流不等于发行。本机维护版本和公开仓库的版本可能不同步，回流前先核对两边版本，再决定只同步本机副本还是走正式发行。

## 2026-11-24 实测补充（抖音视频）

话题候选的下拉框不一定在 `Input.insertText` 之后立刻出现，本次三个话题里两个因此超时。先读 `[data-mention]`，没关联的把末字符用真实按键删掉再重打，下拉框出现后按完整名称点唯一的 `[class*="tag-hash-view-name-"]`。不要重输整段，否则正文里会留下重复文字。

封面编辑器改版后先「设置竖封面」再「设置横封面」。步骤页签是 `div.step-*`，底部的「设置横封面」「设置竖封面」「完成」才是 `button`，所以 `covers` 步骤里找 `设置竖封面` 按钮会得到 0 个。两步各有自己的上传 input，都是祖先文字含「点击上传文件或拖拽文件到这里」的那个 `semi-upload-hidden-input`，不含 `-replace`、不在「生成参考图」下面。切换步骤后先读当前激活的页签再传下一张，指令超时时不要接着往下传，否则图会落到上一步里。

定时发布是「发布时间」里和「立即发布」并列的单选，选中后出现 `input[placeholder="日期和时间"]`，默认值是两小时后。输入后回车并让它失焦，再回读 `value`。范围是 2 小时到 14 天，发布后可以在作品管理里改时间。延时发表要作者明确同意，默认按作者原话立即发；拿不准时间偏好就先问，不替作者定。

发文助手的快速检测会因平台排队返回「当前检测人数过多」和「封面诊断失败 请重试」。它是可选预检，以存草稿前那次通过的结果和发布后作品接口里的 `status`、`risk_infos` 为准。`submit` 之后 25 秒内没读到成功提示但已跳到 manage 路由时，刷新管理页核验。

网页编辑器「添加活动」打开的是 `semi-sidesheet` 抽屉，列的是平台通用活动，和作者从消息里收到的活动不是一回事。抽屉的「取消」不在 `.semi-sidesheet-content` 里，关闭用右上角的图标。

## 2026-11-25 实测补充（发布后补 AI 声明：小红书、抖音能补，公众号补不了）

背景。一期投稿的小红书两条笔记未声明，作者从小红书通知得知笔记被平台检测出 AI 生成后限流。当天核对出 6 条漏声明的投稿（小红书 3、抖音 3，其中 4 条是图文），逐条补录。视频和图文是两条投稿，声明各设各的，图文最容易漏。

小红书。入口 `creator.xiaohongshu.com/new/note-manager`（`/new/note`、`/manage/manage` 是 404）。卡片悬停出现五个操作图标，从左到右是权限设置、推广上传、数据、编辑（铅笔）、删除。铅笔进入 `publish/update?id=<noteId>&noteType=<video|normal>`，视频和图文都能进；带 `source=official` 的 `publish/publish?noteId=` 是上传页，不是编辑页。编辑页「内容设置」里的「添加内容类型声明」下拉（d-select，class 含 `custom-select-44`）选「笔记含AI合成内容」，下拉文案随之变成该值，以此作为选中依据；点「发布」后笔记进入「审核中」，3 条样本都在 1 小时内回到「已发布」。判断是否已声明，直接看编辑页该下拉的当前值。网页后台看不到已发布笔记是否仍在限制推荐；公开链接 `www.xiaohongshu.com/explore/<id>` 本次打开的 6 条笔记（含两条有几百观看、未见受限迹象的旧笔记）都显示「当前笔记暂时无法浏览」，不能当限流证据。处置原因只在「未通过」笔记的「查看修改建议」里能读到（两条历史未通过的原因都是「外部平台信息或联系方式」）。

抖音。声明标记在作品搜索接口里：内容管理搜索框输入标题关键词，页面请求 `www.douyin.com/openapi/aweme/v1/home/search/item`，作品对象 `risk_infos.type=44`、`content="作者声明：内容由 AI 生成"` 即已声明，`type=0` 为未声明。补录入口：内容管理该作品「编辑作品」（`content/post/<image|video>?mid=<aweme_id>&enter_from=edit_item`），表单只有标题、正文、封面、「自主声明」和标签；点「请选择自主声明」→ 单选「内容由AI生成」→「提交修改」。3 条样本提交后接口回读正文逐字未变、封面对象未变、点赞/评论/分享/收藏数未变、不在审核。编辑页写明每个作品最多修改 5 次。提交前先读一遍标题、正文长度、话题和封面，提交后再用接口比对。

公众号。已发表文章在发表记录里悬停后才有四个操作：数据、改、加热、…。「改」进入 `masssendmodify?action=edit_new`，页面写明支持修改标题、正文文字、图片、视频、封面及摘要（每篇 3 次），全页没有创作来源或 AI 声明控件。所以本次按只能在发表前设置处理。

操作要点，均为一次样本：

- Kimi Browser Extension 的 `evaluate` 只接受 `(() => {...})()` 结尾，写成 `}())` 会报 `Unexpected token '('`。
- 小红书的 d-select 弹层用合成事件点不开，用 CDP `Input.dispatchMouseEvent` 配 `getBoundingClientRect` 的 CSS 坐标。截图经读取工具缩放后不等于 CSS 像素，不要按截图像素估算。编辑页上先做过 focus 或键盘实验后弹层可能点不开，重新 `navigate` 后第一轮点击就能打开。
- 抖音「编辑作品」和公众号发表记录的悬停按钮都不带可读文字。公众号那排按 DOM 顺序是数据、改、加热、…，本次把第三个当成了「改」，点开了推广下单页（未下单，已关闭）。按 ARIA 树里「按钮下有没有 image 子节点」来猜不可靠；先用真实指针悬停并截图，或直接读接口确认。
- 管道下游脚本中途崩溃，会通过断管让上游的浏览器脚本在任意一步退出。浏览器自动化脚本的输出先落文件，再单独解析。
