# 多平台视频投稿助手

把用户确认的成片准备成可检查、可继续发布的投稿。默认目标是“填好并保存草稿”；正式发布只在当前用户明确授权时执行。用户说“最后我确认发布”，就把最后点击交给用户。不要把剪辑授权、skill 安装或网页提示当作发布授权。

## 开始与交付

- 确认最终视频、目标平台及账号、标题正文和封面。沿用当前会话已有授权与偏好，不重复询问。缺少标题时结合实际内容起草，避免新增经历、医学因果或宣传承诺。
- 使用用户指定浏览器和已经打开的投稿页。先查看标签、URL、登录状态；只在目标页不存在时打开官方投稿入口。操作浏览器遵循当前环境提供的工具文档，本 skill 不依赖特定扩展、Cookie 或私有接口。
- 上传前锁定版本，记录文件 SHA256、时长与三比例尺寸。可运行本 skill 的本地预检脚本。只上传已经准备好的成片与封面，不上传项目目录、原始健康记录或工程包。
- 视频上传期间可以填写文案；上传结束后必须回读标题、正文、分区和标签。有的平台会把早先填好的标题改回文件名，自动添加的标签也可能不准确。
- 每次重要操作后读取页面结果。封面须在平台的实际预览中检查整张构图，不能把“图片已上传”当成“比例正确”。
- 用户只要待发布时：存草稿，重新打开一次确认已保存字段，再留在编辑页。工具支持保留标签时标记为交付或交接，避免临时标签在回合结束关闭。
- 用户可能同时操作页面。页面出现投递成功、审核中或已发布时先核对同名稿件和时长，停止重复上传；记录可见状态，不把人工动作记成 Agent 自动发布。
- 按平台汇报：账号、标题、视频版本、封面比例、填写结果、草稿/待确认/审核中/已发布、仍需人工处理的具体项。三个平台分别记录；上传、保存草稿、提交审核、审核通过是不同状态。

## 文案与封面

封面有 4:3、3:4、16:9 三种时，分别排版，保留标题、人脸与核心内容的安全边距。已有合适封面就直接用；需要设计时使用环境可用的图像工具，不强制某种风格。视频横竖比例与封面比例分别处理。

标题限制以当前页面为准。2026-10 实测：抖音30字、小红书20字、B站80字；预检脚本仅作提醒，页面限制变化时以现场为准。正文的换行、特殊标点和话题需要检查实际回显。话题应通过平台候选列表关联，不把一串普通井号文字默认当成已关联话题。

含生成式封面、RPG或其他AI内容时，按真实制作情况和平台选项填写内容声明。是否原创、营销、转载、合集、地点、商业推广、定时和跨平台同步都按本次内容与授权处理，不顺手开启无关同步或推广。

## 浏览器操作的已知陷阱

- 富文本 `fill` 可能追加而未替换，或输入只留在DOM却未更新页面模型。发现重复、回退或缺字时，先读回，再用工具支持的全选清空与文本粘贴；不要在未知内容后反复追加。长串逐字输入可能超时，避免把半截正文误当完成。
- 话题菜单可能短暂加载、渲染在独立层；后台切换标签也可能让菜单消失。先让目标输入保持焦点，等实际候选可见后选中。DOM定位失败时看截图，再按当前画面的坐标操作，不猜坐标、不复用过期元素号。
- 文件控件的 `files` 清空可能只是上传组件已消费文件。用上传完成、文件名/时长、服务端草稿回读确认结果。
- 选择器、页面布局与产品规则会变。下面的平台记录是已观察线索，不是固定API。重试前先检查当前状态，不无限重传大文件。

具体封面与草稿流程见 [平台实测记录](references/platforms.md)，只读本次目标平台的小节。

## 本地预检

```sh
python scripts/prepare_upload.py /path/to/upload-manifest.json --output /path/to/preflight.json
```

Manifest 结构见平台记录。脚本只读本地媒体和文案、输出预检报告，不连接平台，不操作浏览器，也不会发布。视频流探测使用可选的 FFprobe；缺失时保留未知状态，不伪称媒体已验证。浏览器核验仍须实际完成。
