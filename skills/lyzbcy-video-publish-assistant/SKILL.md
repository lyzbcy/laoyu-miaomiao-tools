# 多平台视频投稿助手

把已确认成片做成可以审核、继续发布的投稿。默认保存草稿；用户说自己发布时，保留编辑页并交接最后点击。脚本没有公开发布命令。保持当前用户的账号、浏览器和内容授权，不自动加投其他平台或活动。

## 使用方式

1. 沿用会话中的最终视频、目标平台与文案；用manifest记录文件、三比例封面、平台标题/简介/话题。设置 `video_sha256` 锁定版本。实际使用的账号在首次打开页面时检查。
2. 优先运行 [脚本工作流](references/automation.md)，不要为每次投稿重写上传、鼠标、富文本、话题循环。`profiles.json`单独维护网页选择器。当前脚本使用已安装的Kimi扩展和本机Edge登录态；先读可用的`kimi-webbridge` skill。没有桥接时仍可用环境提供的浏览器工具完成同一流程，不索取Cookie。
3. 先`inspect`确认页面，再按步骤或`prepare`执行。复用同一个`--session`、`--run-dir`。上传尝试会预先入账；遇到超时先回读，不能凭超时判断失败并重传。已有其他标题的编辑页不覆盖。
4. 脚本设置封面后留下截图检查点。用图像工具检查**平台实际预览**，确保标题、人脸、副标题和比例正确，再记录`review-covers`继续。它是Agent视觉验收，不是额外索取用户批准。已有合格封面不重新生成。
5. 保存后重新打开，核对标题、正文、话题实体/标签、声明、封面和上传状态。`verify`不替代视觉检查。用户可能正在亲手发布；出现已提交线索时核对实际状态，避免重复上传，不把人工发布计作脚本发布。

## 实测边界

- 文件选入、上传完成、保存草稿和公开发布分别记录。文件选择只写入已观察的真实页面控件；扩展文件权限仍须开启。
- 文案以回读为准；话题通过准确候选成为实体。可信鼠标、富文本光标、隐藏文件框、闭合Shadow DOM已封装；选择器不唯一就留存现场，不盲点。
- 首次运行不下载浏览器、模型或npm包。依赖Python标准库、系统curl和已有浏览器桥；FFprobe为可选本地探测。上传流量等于媒体封面所需流量，平台页面另计。
- 网页会变化。三国内平台适配来自两次实操；新版脚本不通过再次上传成片来复测。YouTube的文本、8个标签、声明、语言/类别和私享回读另做现场验证。只推荐的平台不算已接入。
- YouTube保留私享/草稿。音乐版权检查结果单独交接，“无版权警示”不等于“无版权主张”；不替用户发起争议或删改音乐。

封面、声明与平台差异见 [平台记录](references/platforms.md)，仅按需读取。未指定原创、推广、地点、合集、定时或同步时，不为了填满表单开启无关选项。

## 交接

按平台列账号、标题、封面比例、保存/回读结果、待处理事项和编辑页。运行现场、账号、截图和稿件链接留在用户项目的run-dir，不进公开技能包。技能源码、安装目录和release ZIP版本保持一致；遵守仓库要求同步入口下载链接。
