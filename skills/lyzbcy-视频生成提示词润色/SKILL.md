# 视频生成提示词润色手册

这份 skill 的目标只有一个：**把分镜提示词里"会污染形象还原"的内容删干净，只留下镜头语言本身**。

角色长什么样、穿什么，由单独的**角色形象图(art)** 在生成时锁定注入；场景长什么样，由**场景图**锁定注入。提示词再写一遍颜色、款式、材质，模型就会在"听提示词"和"听图"之间摇摆，反而偏离形象。而且同一角色在不同集会换装，写死颜色一旦和当集 art 对不上就是硬伤。所以润色的主基调是**减法**，不是加法。下面的规则都是从实战纠错里来的，每一条都标注了为什么——完整规则分域放在 references/ 里，按模式按需精读，不必一次全读。

范围仅限分镜润色——场景/角色资产生成、剪辑、音效 BGM 等其他环节的内容不收录进本 skill（2026-08-18 用户定调）。例外：跨集一致性基准（VoiceID 基准、方向基准、资产状态清单）和润色交付的资产需求清单，是润色自身的准确性与交付完整性所需，属于本 skill（2026-08-21 修订）。判断标准：为"逐镜提示词正确"服务的进，服务剪辑/生成环节的不进。

## 使用前：静默更新检查（**每天首次使用**时执行）

**每天首次使用**本 skill 时，先按 `references/update.md` 的三源静默对齐流程自检一次（本目录 / 仓库副本 / 线上 raw 直链，谁版本高听谁的，多文件整包更新，失败用旧版），当天后续使用不再检查。总原则：静默、不询问、不阻塞本次润色任务。运行状态记录在同目录 `.update-check.json`。

## 全量润色工作流

收到一段分镜提示词（通常含多个镜头）后，按这个顺序处理：

0. **开工预检（润色开始前一次做完）**：
   ① **台词逐句对照原剧本**（规则见下"台词核对"）；② 检索全集分镜，统计每个角色 VoiceID 各写法次数，以多数派为基准、只改异类（→ references/voice.md）；③ 算每个分镜文件台词总字数 ÷ 可用总时长（硬上限−0.5s 余量；**上限按本集所用模型定：C2.0=15s、C2.5=30s，开工先确认模型**），>5 字/秒的文件先整体重排再逐镜配时长（→ references/shot-tech.md）；④ 跨集连续场景先读上一集的交接快照（→ references/delivery.md）；⑤ 检查项目目录是否符合规范（→ references/delivery.md §项目目录规范）——不合规先问用户要不要整理，同意才动手（只移动/重命名，不改内容）。
1. **定场景基调（光线+站位+方向基准）**：通读全部镜头，为本场定光线/色调基调、**人物初始站位和左右方向基准（轴线）**，一起写在场景头部（→ 精读 references/scene-anchor.md）。
2. **逐镜删污染**：过红线清单——删角色外观（颜色/款式/材质/配饰）、删场景材质、删身份定语、删草稿私加的空间结构词、删分镜间转场镜头（→ 精读 references/redlines.md）。
3. **核景别与时长**：逐镜核对景别与拍摄对象是否匹配、机位高度、时长与对白字数是否匹配（→ 精读 references/shot-tech.md）。
4. **查跨镜一致**：光线、人物站位、左右方向（轴线）、角色称呼、VoiceID 在全场是否前后统一；站位关键变化（跪/起/移动）处是否点明；提示词层面不能自相矛盾（对照 references/scene-anchor.md、references/voice.md）。
5. **出结果**：按"交付格式"给润色后的提示词 + **极简改动说明**（每条一句话：删/改了什么、为什么）。交付前可用 references/checklist.md 逐镜终检；整集交付的配套产物（资产需求清单、跨集交接快照）见 references/delivery.md。

改动说明只讲"动了什么"，不要长篇大论复述规则。

## 三段式管线（可选：深度润色 / 交叉验证）

用户明确要求"**深度润色**"或"**交叉验证**"时，在全量润色外加挂官方审校层（**默认不启用**，单跑本 skill 即可）：

1. **第一轮·本 skill 润色**：按全量工作流走完，产出润色稿。
2. **第二轮·sd25-pe 官方审校**：把润色稿逐镜交给官方 skill `sd25-pe`（已安装到 `~/.agents/skills/sd25-pe` 则按其规则审校；未安装则提示用户运行安装命令，见 references/seedance-2.5.md）。重点看：有没有不适合 C 模型的写法、素材指代表达、术语规范。
3. **第三轮·本 skill 终检**：对 sd25-pe 的每处修改逐条判定——**与跨镜一致（VoiceID/轴线/站位承接）冲突的回滚，与红线冲突的回滚，其余可吸收**。终检后交付。

原则：sd25-pe 是"单镜冠军"，本 skill 是"全场教练"——它每次调用只看得到单镜和本次素材，看不到全集与上一集，**凡涉跨镜的判断以本 skill 为准**。

## 台词核对（台词模式 & 预检①共用）

- 润色时必须回归原剧本**逐句核对**台词——草稿常擅自压缩/改写（第62集"坏人"被改成"白衣公子"的教训），发现先恢复原文再润色。
- 台词是硬约束，**一字不改**；拆分到多镜头说的，合起来也要与原文完全一致。
- **对白账本**（官方 sd25-pe 升级版）：逐镜过账——镜头 → 说话人 → 台词原文 → 受话人 → 其余人**自然闭口聆听**。不得把已指定说话的镜头改成静默，不得交换说话人；多人对话逐镜标注说话人，防止两人同时开口。
- 剧本只给台词**片段/关键词**时，对白只保留该片段，氛围用表情/动作/语气承载，**不得补写前后不存在的完整句子**（官方例：只说"你一个外人"，不得扩成"你一个外人，有什么资格……"）。
- 剧本的**表演指示词**（如"邪魅一笑"）不等于台词，照抄进提示词会把模型带偏——翻译规则在 references/redlines.md §4。

## 正面清单：提示词应该写什么

删完污染词后，提示词要保留和强化的是**纯镜头语言**：

- **景别**（且匹配拍摄对象）
- **镜头运动**（三档写法）：通识词直接写（推/拉/摇/移/跟、环绕、低角度、俯视）；热门词直接写（一镜到底、希区柯克变焦、FPV、子弹时间、手持、回弹变速）；**小众术语 = 名词 + 可观察展开**（"移焦，焦点从前景树木转移到背景人物，前者渐模糊后者渐清晰"）。任何运镜都要带**作用主体 + 起止状态**，不能脱离主体只甩术语
- **构图**：引导线、对称、对角线、前景压迫…（构图元素用结构词，不锁材质）
- **角色名 + 动态/动作**（部位名可作载体，不加颜色材质）
- **道具功能名**（仅当它是动作关键对象）
- **情绪**（量化百分比，写在"情绪："行）
- **光影方向 / 色调**（跨镜头统一，见 scene-anchor.md）
- **人物站位 / 空间关系**（场景头部锚定初始站位，站位变化点明，见 scene-anchor.md）
- **全场方向基准（轴线）**（谁左谁右写进基调行，全场沿用，见 scene-anchor.md）
- **多状态角色括注所用资产**（角色有多套形象资产——健康态/受伤分级/进化形态/换装——时，每个涉及该角色的镜头括注本镜用哪套，如"小夜（资产：受伤2级）"；不标，制作时不知道拿哪张首帧图，事后补是纯返工）

抽象氛围词（"沉重压抑""紧张"）尽量只留在"情绪："行量化表达，不要在画面描述里堆砌；也不要把它们替换成具体材质物件（会和红线 3 冲突）。需要强化氛围时，落到**光影/机位/姿态层**（冷调、侧逆光、低机位仰拍），不落到具体物件，**更不落到改造场景结构**（改结构=换场景，与场景图冲突）。

**每个镜头必须携带戏剧节拍（导演思维）**：一个镜头要么有动作、要么有情绪变化、要么有信息递进——纯交代的"定位镜头"（如"某某站立，脚下纹丝不动"空转 2 秒）是废镜头。修正站位/光线等问题时，把站位信息**织进有戏的动作里**（打量、欲言、拢袖、转身），不能为修问题牺牲镜头信息量；相邻镜头之间要有衔接钩子（上镜末"欲言"接下镜开口），不能两镜各自静止、互不衔接。运镜尽量保留动态语言（呼吸式微推、缓慢跟移），全固定机位会让整幕发死。**重写是为修目标问题，不是从头创作**——原稿里有效的转折节拍与好细节（如"带笑的嘴角一点点抿直、眼神沉淀"）必须保留，删掉它们等于制造新问题。

**因果揭示镜头先因后果**："出现原因后人物才改变表情/动作"的镜头，先让观众看清**触发原因**，再给**反应**；距离远时用一次视线或镜头转移建立关系，能同框就同框保留原因与反应；**不得在原因被看清之前过早推成纯面部特写**，也不得只给反应特写而漏掉触发原因。

## 素材指代（多参考素材时必写）

分镜若走"参考素材注入"通道（角色 art、场景图、音色样本等作为图/视频/音频参考上传），提示词头部必须**文本绑定**每份素材的职责——不写，模型可能映射错乱（多人时张冠李戴、角色重复）。规范源自官方 sd25-pe：

- **一行一主体**：一行只定义一个主体及其参考，写清"采用什么 + 不采用什么"，**禁止范围句**（"人物A和B参考图1、2" ❌）：

```
图1用于姜羡宝的五官、发型和服装，不采用图片背景。
图2用于厢房的空间布局和光线，不采用图中人物。
音频1用于郝有财的音色。
```

- **映射信息绝不写在图片上**——图上写名字、提示词里叫名字，多人时必混淆/角色重复。
- **参考已锁定的信息只指代、不复述**（官方版减法）：art 已锁外观，提示词不再描述外观；参考视频已给动作，只写"严格参考视频1的动作与运镜"，不必逐动作复述。
- 多状态资产在对应行注明（"图3用于小夜（受伤2级）的形象"）。
- 上传了但本镜不用的素材，列一行 **【未采用素材】**（"图4、音频2未参与本镜，不用于人物、场景、道具或声音"），防止模型自行激活。

## 交付格式

- **分镜文件首行标注总时长**：交付整个分镜文件（而非单镜头片段）时，在文件第一行统一标注 `【分镜总时长：Xs】`（X 为该分镜所有镜头时长之和）。视频生成工具每个分镜都要填总时长，放首行打开即可抄，不用翻底，也便于一眼核对整集时长；时长先按各镜头字数配好单镜时长，再求和。注意：**这是给操作者/工具填参数的文件标注，提交提示词时不抄进 Prompt 正文**（官方参数分离原则：画幅、总时长、分辨率、声音开关由工具界面设置，不进提示词）。
- **声音/台词符号**（与 C 模型原生格式对齐）：台词 `{原文}`；音乐 `(舒缓的钢琴乐)`；音效 `<远处传来钟声>`；字幕 `【第一章】`。配音指令保持"VoiceID： 音色 + 状态/语气： 档位"两段式不变，台词正文统一用 `{}` 包裹；用了 `<>` 标音效后，角色名不再用尖括号，避免同符号双职责。
- **模板**：

```
【镜头N 润色后】
<润色后的提示词原文>

改动：
- 删"XXX"：原因（如：锁定服装颜色，与 art 冲突）。
- "近景"→"特写"：拍摄对象是脚步，景别不匹配。
```

- 多个镜头按顺序列出；用户只问某一个镜头就只给那一个，但跨镜一致性的问题（如光线）即使别的镜头没问到也要点出来。
- **单功能模式**在文末加"**另发现**"一节，列发现但未修改的问题，等用户发话再处理。
- 整集交付的配套产物（资产需求清单）与多集批量流程、跨集交接快照 → references/delivery.md。
