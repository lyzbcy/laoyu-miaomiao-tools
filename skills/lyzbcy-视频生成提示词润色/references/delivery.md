# 交付配套与多集批量（整集交付时读）

## 项目目录规范（开工预检⑤检查）

一个剧一个根目录，剧本合订、一集一夹、分镜按序号排：

```
剧名/                          ← 项目根目录（如 将作妖/）
├── 剧本.docx                  ← 全剧剧本：单个 doc 文档，第 1 集到最后一集都在里面
├── 角色配置.md                ← "人员配置"：每个角色的 VoiceID 基准写法 + 状态资产清单
│                                 （健康态/受伤N级/进化形态/换装各套 art 的文件名与存放位置）
├── 场景清单.md                ← 已有场景图及适用范围；预检"引用的场景资产必须存在"查这里
└── 第NN集/                    ← 一集一个文件夹，集号即文件夹名
    ├── 01.md … 16.md          ← 分镜文件按播放顺序两位数编号，文件名排序 = 播放顺序
    ├── 交接快照.md            ← 本集交付时生成：末镜站位/方向基准/状态资产/VoiceID 基准
    └── 资产需求清单.md        ← 整集交付配套产物
```

- **从字字动画导出分镜（上游入口）**：字字动画生成的分镜存在本机任务库（`%APPDATA%\zizidonghua\task_records.db`），用 `python scripts/zizi_export.py` 列出全部分镜 → 选定 → 按本规范格式直接落到 `第NN集/01.md…`（自动求和标注【分镜总时长】、镜头N/情绪各自成行）；只读数据库，不动字字动画本身。
- **剧本 = 单个 doc 合订本**（用户实际工作形态）：台词核对前先用 pandoc / python-docx 把目标集文本抽出来（以"第N集"标题分界），再逐句对照；抽不出来时让用户直接贴当集剧本文本。
- **分镜文件名固定两位数序号**（01、02…），资源管理器默认排序就是播放顺序；分镜超过 99 个才升三位数。交付时"多镜头按顺序列出"以文件名序为准。
- **角色配置.md 就是 VoiceID 基准文件的规范位置**（下方多集批量第 2 条读的就是它），也是"多状态角色括注"核对资产名的地方。
- **目录不合规时的处理**：开工预检发现实际摆放不符合本规范（分镜散放、命名无序、找不到剧本/角色配置），**先询问用户"要不要按规范整理"**；用户同意才动手，整理**只做移动和重命名、不改任何文件内容**，整理完用一句话报告动了哪些文件；用户拒绝就按现有结构干活，不反复劝。

## 整集交付的配套产物

① **资产需求清单**——本集用到哪些角色状态资产、哪些场景图，已有/缺失（"多状态角色括注"的汇总副产品，制作排期直接用）；② 多集任务时附**跨集交接快照**（末镜站位/方向基准/状态资产/VoiceID 基准）。

## 多集批量任务：逐集落地，不开长流水线

连续润色多集时上下文随集数膨胀，连贯性 bug（站位瞬移、跳轴）恰恰出在最后处理的那集——不是规则缺失，是注意力被稀释。

1. **一次只开一集**：当前集完整走完"第 0 步预检→润色→清单核对→交付→沉淀"并落盘后，才开下一集。
2. **每集开工重读基准**：不依赖会话上文残留，开工先重读本 skill 站位/方向/VoiceID 关键规则（references/scene-anchor.md、references/voice.md）+ 项目的 VoiceID 基准文件（规范位置：项目根目录 `角色配置.md`，见上「项目目录规范」）。
3. **跨集交接快照**：每集交付时写一份交接快照——上一集末镜站位/姿态/位置、未完结场景的方向基准、各角色状态资产与 VoiceID 基准。下一集第 0 步先读它。
4. 上下文明显过载（开始忘规则、重复问）时，主动建议用户**开新会话处理下一集**，以交接快照为新会话输入。
