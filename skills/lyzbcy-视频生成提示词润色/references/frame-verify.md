# 抽帧验证闭环（省钱关键）

视频按秒计费（约 ¥1.5–2/秒），直接拿提示词生成视频去"试错"非常烧钱。润色完的提示词，**先走一遍文生图抽帧验证，通过了再花钱生成视频**——这一步能筛掉八成的方向性错误，把大钱只花在确认过的提示词上。

## 能验证什么 / 验证不了什么

- 能验证（静态画面）：景别、构图、角色站位、光影方向、场景空间、角色外观是否和 art 一致。
- 验证不了（运动与时序）：镜头怎么推、衣摆怎么翻、人物怎么动。运动仍需视频模型小批量试，**文生图通过 ≠ 视频一定没问题**。

## 生图方案（先探测环境，再让用户选）

1. **本机有 codex CLI**（`codex --version` 能跑通）：询问用户**是否使用 codex 的生图额度**进行生图；同意则走 codex 出图。
2. **本机没有 codex CLI**：给用户两个选项，等用户选定再动：
   - ① **使用 codex 生图**（需先安装并登录 codex CLI）；
   - ② **本 skill 输出完整的生图 prompt**（已按下方切分图格式写好每格放哪个分镜），用户复制到自己选的任意生图软件出图，把图拿回来交给本流程继续。
3. 无论走哪条路，出图后都回到本 skill：跑切分脚本 → 人审 → 出验证结论。

> 漫剧角色一致性要求高，生图通道尽量选支持**参考图/主体一致性**的（把角色 art 当参考图锁外观）；通道不支持参考图时，抽帧验证只核"方向/构图/站位"，外观一致性留给视频生成阶段用首帧 art 兜底。

## 切分图设计（省额度关键：一张图审 16 帧）

生图按张计费，一张 4×4 网格图装 16 个分镜画面，验证额度直接省 16 倍：

1. **写 prompt 时就分格**：prompt 里明确写好每格放什么——"第 1 格放分镜01镜头2，第 2 格放分镜01镜头3……"，每格描述保持简短（主体 + 景别 + 关键站位/构图），格与格内容互不干扰。
2. **出图后跑切分脚本**：`python scripts/split_grid.py 网格图.png --labels "分镜01-镜头2@0:03,分镜01-镜头3@0:07,…"`（labels 按**从左到右、从上到下**的格子顺序，共 16 项）——脚本把图切成 4×4、画红色切分线，**每格左上角标注"分镜号-镜头号@该画面出现的时间（分:秒）"**，同时输出整张标注图 `grid_annotated.png` 和各格单格图；小批量可用 `--rows 2 --cols 2` 等任意网格。
3. **人审看标注图**：一张图扫完 16 帧——哪格是哪个分镜、画面出现在第几分几秒，角标上都有，不用来回翻文件。

> **⚠️ 网格服从度 warning（2026-09-01 实测）**：flux / pollinations 这类模型**不服从"N 格网格"指令**——要 2×2 四格会自由发挥成 3×2、3×4 不等，格数和内容都失控。网格生图必须用**多主体/版式服从强**的模型（即梦、Seedream 等）；模型不行时的合法变体：**逐镜单图生成 → PIL 拼成网格 → 再跑切分脚本**，标注效果等价，只是省额度的好处没了（免费通道无所谓）。

## 闭环步骤

1. 按上述生图方案出图；**默认走切分图**（一张 4×4 装 16 镜），重点怀疑的镜头可再单独加抽。
2. 跑切分脚本 → 人审两看：① 画面方向对不对；② 角色和 art 一致吗。
3. 不过 → 反馈问题，用本 skill 改提示词 → 重抽帧。
4. 通过 → 才送图生视频（大钱花在这步）。
5. 成本控制：一张 4×4 切分图 ≈ 16 镜的验证量，只花一张图的额度；能用 codex 生图额度或免费通道就不花钱。

验证中反复出现的错误（某种描述总让角色穿错衣服之类），抽象成新规则写进对应 reference（redlines / scene-anchor / voice / shot-tech），并在沉淀记录加一行——验证越多，返工越少。
