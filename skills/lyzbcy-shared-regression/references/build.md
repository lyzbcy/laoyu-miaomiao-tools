# 从构建开始避免已知问题

本文件是构建与改版时的设计输入。先落实四项核心体验：精准设计映射、PRD独立窗口/系统置顶/原文蓝选、辅助演示、本地服务就绪与有界预载。不要先造结果表单，再等用户逐项指出核心体验缺失。以下为已有演示台实测问题的通用蒸馏，不表示公开模板已实现全部功能。

## 构建前先定的数据和职责

- 一份用例定义供演示、人工回归和AI执行使用；每条包含稳定ID、负责人/范围、PC/H5入口、真实前置、步骤/预期，以及对应PRD正文、设计状态和演示适配器。映射可分文件，不能复制出互相漂移的第二套用例。
- 单独配置环境origin、各端入口、前端模块版本、后端请求lane、资料源及适配器；不把开发者路径、租户ID或某次特性版本写成通用默认值。
- UI初始化显式等待资料及增强模块就绪，再解析深链、筛选与渲染。环境恢复、预载、导航和演示使用清晰生命周期，避免多次包裹同名函数后互相覆盖或依赖脚本偶然加载顺序。
- 先查既有服务和脚本，只补缺口。保留现有记录、浏览器配置及他人并行改动。首版也要明确已实现、仅有指导和未适配三种状态，不能把方法文档等同于运行功能。

## 本地服务就绪与页面预载

服务准备和业务页面预载是两件事，两者都需设计：

1. **准备服务**：启动清单包含PC、H5、对照台资料服务及PRD定位/浏览器连接依赖。健康检查核对预期HTTP页面或API内容、辅助协议版本和扩展实际连接；端口监听、进程存在或请求200均不能单独证明目标服务就绪。
2. **恢复缺失服务**：只启动缺失且归本项目管理的服务；并发恢复请求合并，启动中进程登记并复用。端口被无关服务占用、旧协议未重启、扩展断连时分别报错，不杀未知进程，不覆盖现有服务。
3. **只预载合适对象**：首屏可用后延迟预载少量后续设计图及最多一个待用业务页面；本地、允许的只读入口才进入页面预载。测试/生产环境默认不后台预载；有草稿、演示或临时状态时暂停相关预载。不为预载提交数据或触发有副作用的初始化。
4. **页面复用要保活**：相同URL复用当前iframe；待用iframe转可见时在原DOM位置切换身份/样式，不移走再插入，否则会销毁已加载文档、重新初始化。iframe加载事件不等于身份、路由或业务数据就绪，应分开显示。
5. **缓存有界且可失效**：提供预载开关、状态、容量与时效；示例已用单待用页、图片上限及短TTL，具体数值随项目配置。身份、环境、版本、入口或筛选变化时丢弃不匹配缓存。手动刷新清待用页再读当前页；关闭预载取消计时及待用iframe。
6. **可访问性与恢复**：隐藏页不得抢焦点、参与键盘导航或干扰当前操作；转为可见时恢复标题、键盘可访问性及事件绑定。失败可回退正常加载，不拿白屏或过期预载冒充已完成。

## 已踩坑 → 构建约束 → 可观察验收

| 已观察问题 | 构建时落实 | 验收方式 |
| --- | --- | --- |
| 多条用例统一显示主列表旧图 | 按用例/入口/状态映射，单例覆盖优先；显示来源版本，说明手动图覆盖 | 切换列表、弹窗、PC/H5及不同状态，逐项核图；不只检查图片HTTP成功 |
| 能开原文链接却没有独立PRD工作窗口 | 独立窗口复用，系统级置顶/取消；窗口适配器与普通网页能力分开 | 实际打开/复用、置顶再取消，切换其他窗口后观察 |
| 目录选中了却宣称正文已蓝选 | 准确短句唯一命中，原生正文选区，并核对所选文本 | 连续定位两段不同正文，再验证多命中、未命中和连接断开 |
| 后台窗口停在about:blank | 导航流程不依赖requestAnimationFrame或前台焦点才能继续 | 后台打开、切回、整页刷新都能恢复实际页面 |
| 扫码成功但跨站iframe仍未登录 | 区分第一方与分区会话；复用项目既有授权机制，不导出凭据；保留独立登录路径 | 实际身份接口和业务页验证；复制完成提示不算登录有效 |
| 已登录却仍加载旧版模块或错误lane | 前端模块、运行时上下文、后端lane分别核验，保留大小写；在路由就绪后恢复 | 核实际加载文件及真实请求，刷新/切端后复查，不只看storage |
| H5深链缓存旧路由，误判无权限/未开通 | 先正常入口完成身份/dashboard初始化，再进入业务路由 | 核当前身份、正常页签和目标路由；不凭缺页签下业务结论 |
| 切换用例/刷新后PC/H5入口丢失 | 按用例记忆所选入口并校验仍属当前links；环境配置分别保存 | PC→H5→别例→原例、iframe刷新和整页刷新 |
| 技术用例深链静默跳第一条 | 先解析指定ID与范围，再选正确模式；ID不存在明确提示 | 从默认列表之外的用例深链打开，ID不被替换 |
| 空筛选残留上一例业务页与设计图 | 空结果清当前对象、旧图/iframe及待用缓存，禁用相关动作 | 搜索无结果后无上一例可操作内容，清搜索能恢复 |
| 慢增强脚本导致显示模式与真实列表不一致 | 显式初始化顺序，丢弃过期响应，事件只绑定一次 | 延迟资料/增强脚本后仍按正确模式和深链初始化 |
| 辅助演示只有按钮或文字，无实际动作 | 用例绑定可执行适配器；明确逐步/自动、停止、错误和恢复 | 实际执行代表流程、取消/中断及切例，检查草稿/临时状态恢复 |
| 受控草稿、假响应或HTTP检查被记成全例通过 | 标注证据类型与覆盖检查点，演示和成绩分离 | 未测保存、权限、跨端项保持pending/partial |
| 通知用例只有普通列表入口，无从验证 | 定义真实前置和通知URL，缺样本明确阻塞，不虚构入口 | 原链接打开正确对象；无权限/不存在需对应样本，不擅自发通知或改权限 |
| 折叠区、后台页、多窗口重复抓接口明细 | 需要时才扫描；后台/折叠暂停，合并同类请求并限制并发 | 打开多个页面和折叠观察区后看请求量，不重复排队 |
| 较晚备注把别人失败与证据覆盖成通过 | 按字段合并真实变更，或用追加记录；保留不同身份和同字段冲突 | 两窗口基于旧值，一方改失败/证据，另一方只改备注，刷新后仍保留失败及证据 |
| 备份缺字段误作删除，前版本签名递归增长 | 区分字段缺失与显式清空；签名排除自身；冲突去重 | 新旧备份往返、主动清空和连续编辑，核历史与记录体积 |
| 改了源码但浏览器仍是旧逻辑 | 动态资料按需禁缓存；JS版本与HTML同步，核实际HTTP内容 | 旧标签刷新后加载新版本；不把所有映射错误都归因于缓存 |

## 最小交付验收

按实际改动选相关场景，首次完整构建至少覆盖：

- 缺服务恢复、异常占用、并发启动合并与扩展断连提示。
- 默认范围、深链、空筛选、慢初始化；负责人/移交边界正确。
- 同页复用、预载命中、预载关闭、主动刷新清缓存、过期和环境切换失效；不多发业务写入。
- PC/H5往返、两类刷新、身份及前后端版本核验；已有草稿不覆盖。
- 三种不同状态的设计映射；PRD独立窗口/置顶/取消/两段正文蓝选及错误反馈。
- 一条实际辅助演示、停止/异常恢复；人工/AI结果及冲突保留。

脚本/模板检查、受控浏览器验证、真实环境验证分别记录。未验证功能明确列出；不能把本机构建或通用模板通过说成其他项目已具备全部体验。相关检查通过且无新改动后交付，不循环截图拖延。
