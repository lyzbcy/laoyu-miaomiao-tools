# 声音按叙事作用分配

## 先选主线

| 内容需要 | 声音安排 |
| --- | --- |
| 操作存在理解缺口 | 简短人声解释关键因果，音乐按可懂度避让 |
| 音乐承担情绪与节奏 | 保留乐句连续，动作和短心声进入音乐空间 |
| RPG逐字心声 | 轻短哔声回应文字或短语，不启用人声duck，不切断演唱 |
| 真实操作/人物反应 | 保留有价值原声，事件声回应触发与反馈 |

不默认每条连续旁白，也不以配乐代替产品解释。选曲认可只证明音乐选择，不能证明成片好。RPG哔声可按文字密度稀疏触发，控制高频和峰值；歌曲连续不等于所有影片禁止duck。

## 选曲与画面试听

先检查原片音轨并试听开头、等待和情绪峰值，区分原声、游戏声和已有配乐。没有独立系统声轨不能推出混合轨中没有BGM；不重复叠加掩盖原声。按剧情/反应建立情绪段落，再从用户或创作者/系列配置读取语言、年代、偏爱与排斥项；例如偏好1990—2010年中文曲目只适用于相应创作者，不成为所有项目的固定歌单。没有既有偏好时再询问，不反复确认已经给出的选择。

给具体歌曲及版本，配实际视频、原声与预计混音试听；通常可用2—3个短段覆盖口播、情绪高点和一次切歌，数量与长度随素材调整。只给歌名、纯音乐或“热门/搞笑”方向不算画面试听。用户要求先试听时，确认后再扩展全片；已确认的选曲直接复用。GitHub项目可用于发现工具，不证明曲库适配；本轮用户采用不证明爆款或留存提升。

在项目保留音源/使用条件、文件哈希、歌曲版本、源入出点、成片区间、情绪、ducking、切歌和用户确认状态。全片使用实际可用长音源或有意的完整编排，不把短试听反复循环冒充完整选曲。版权检测结果逐平台交给发布端；熟悉或热门不代表可跨平台自由使用，原创声明不替代音乐授权。

## 配音、识别与歌词

普通中文旁白可沿用哈基米风格的曼波偏好，用户当前指定优先；缓存需匹配文本、音色、语速及哈希，新生成先按下节核实可用服务并试听。TTS朗读、原声识别、器乐合成、带唱歌曲和分轨是不同能力；需要歌曲生成再读[music-generation](music-generation.md)。记录来源与使用限制，不承诺平台一定无版权主张。

字幕优先依据已有稿件和实际WordBoundary/音频时间戳，缺边界时另行对齐。唱词以实际选定录音核对，ASR尤其可能误听前奏碎唱；原稿、识别与人声/能量边界互证，不能把未检出的Outro或猜测唱词当事实贴上。改文案、音源或片头后重新核对首句、段落、动作和尾音。

歌词与心声分别排版；歌词按真实演唱出现，器乐段按表达需要收起。竖排只是避免争位的一种方案，仍检查手机阅读。

需要云端字级转写时先读[免费用量准入](cloud-transcription.md)，按实际待上传输入计量，核实API模型/余额/重置并取得明确批准；没有可核实余额不自动付费。已有本地模型不等于第三方字级接口已适配；删段后按[EDL映射](editing.md)重算字幕并复听字头尾和接缝。

## 默认中文配音（跨电脑）

曼波是音色偏好，不绑定永久可用的服务。先核对用户已确认的声音样本与缓存；换服务时同名音色也要试听，不用名称代替声音一致性。新增引导语记录前一句结束/页面出现等事件锚点及绝对时间，配音不叠压原口播，改词后同步双语字幕。

历史 Milora mbAIsc 适配为 `https://api.milorapart.top/apis/mbAIsc`；曾观察到试用下架、需要月包，不能把旧成功记录当作当前服务可用。下列命令仅在本次已核实该服务、音色和费用可接受时使用；它没有实现剪映或其他服务的自动切换。用户已批准的其他在线服务可按其实际适配生成，接口、会话和私有响应留项目，不随包公开。

从skill根目录执行（只需要Python 3标准库和网络）：

```sh
python scripts/narrate.py --text "来来来，刷 Hot 100 的朋友们，今天复习 LRU 缓存。" --output work/narration/intro.mp3
python scripts/narrate.py --text-file work/narration/intro.txt --output work/narration/intro.mp3 --speed 0
```

文本文件使用UTF-8。接口参数为`text`、`format=mp3`、`speed=0`（默认）；先返回JSON中的`code=200`及音频`url`，脚本再下载MP3。旁边的`intro.mp3.json`记录来源、文本、语速、音色及SHA-256。相同文本和参数且文件哈希匹配才命中缓存；同名文件不匹配会报错，改用新输出路径，不覆盖已有录音。最终仍需检查发音、实际语速、首尾音和字幕时序；脚本不生成字级时间戳，也不证明完整听审。

服务不可用、返回异常或音频格式不符时退出报错，不静默换成Edge TTS、下载模型或无限重试；保留已有录音，说明阻塞，再按用户后续选择处理。接口会接收朗读文本，敏感内容按项目隐私要求处理；不把当前可调用当作永久免费、长期可用或无版权主张的保证。用户明确指定其他声音时按其要求。带唱复习继续使用Suno等歌曲工作流，本脚本只做口播。

## 原声修复与切歌

保留未处理原声；开头或局部麦克风有问题时先做局部轻降噪/EQ/增益的A/B样本，复核自然度、辅音、呼吸、底噪和处理延迟，不默认整片强降噪。

原声、音乐、音效及新增配音分支处理。口播处平滑避让、句尾自然释放；高燃无口播段可抬升音乐，有口播时仍以可懂度为先，不将整片音乐压到不可感知。切歌先对乐句、节拍和能量，必要时检查调性；DJ搓盘按用户风格选择，短促衔接而不盖住反应，不强制每次使用。仅瞬态入点对齐不宣称严格beatmatching或调性匹配。

## 混音与验收

事件音效按动作建立清单和时间点：触发、冲突、连续操作、状态确认、纪录变化、揭晓与互动反馈，各自选择合适材质；连续缩框等多次可见动作不能只在整段开头响一次。先覆盖有意义的事件，再删重复和抢话声，不为凑数量给每个字配同一种哔声。用户反馈“音效少”时对照真实动作与导出混音补缺，并实查落点和电平。关键事件标在时间轴：提醒、反应、按键、揭晓、落地或恢复。重点前先判断画面减量是否已足够，不默认把音量降低或插入静音；确需声音收放时保留句意、呼吸和乐句，按当前音源决定音效减少、编配变薄或适度避让。歌曲要求连续时不得为了所谓呼吸点切断歌词或硬门控。区分材质与情绪，留出疏密，不以音效数量证明设计好。先比较一个代表片段的音乐/人声与加入事件声后的效果；声音参考见[复盘依据](lessons.md)，其入库记录未耳听，不冒称优秀听感标杆。

用户要求BGM/音效时，不能只写进工程说明：沿用可核实授权资源或本地合成，口播处避让、开尾淡入淡出；情绪转折留停顿，喜剧音效短促且不盖人声。检查实际导出混音与非静音支路，防止漏混。正常速度听清辅音、段间空白、尾音、高频哔声、音量突变和歌曲衔接；同时查叠加峰值。约-14至-18 LUFS可作短片参考，听感与平台要求优先。若要求歌曲不中断，另查剪切/门控/增益变化；数值连续不替代主观试听。未完整耳听如实记录。最终编码后试听开头、轻声、情绪峰值、每次切歌及新增配音前后；手机外放/耳机的可懂度、音量突变与同步分别记录。源音频试听或数值合格不替代最终编码音频检查。

## 依赖与获取口令

优先现有字幕、服务边界和已安装模型，不为普通配音部署Whisper或歌唱/分轨环境。大型下载先说明用途、体量与现有资源为何不够并取得授权；模型位置遵从当前设备的存储约束。模型目录由项目配置，调用前检查离线复用；素材传输与依赖下载分别记录。

获取口令按当前产品、渠道和网址限制制作。只展示不读时保持稳定可截图；阅读时长和字号按实际画幅判断，不复制历史产品指令。口播和歌词不新增兼容、隐私或安装成功保证。


## 动态双语字幕与可感知的音乐床

完整制作先明确字幕语言、显示代称和样式，第一版完整片即交齐约定字幕；强调字卡不代替口播字幕。先用最长句、快速口播及关键UI做手机阅读小样，优先轻量自适应底框，具体样式按用户审样，不套固定大黑框。用户要求双语时，为每个实际口播语义段提供对应译文，在 Remotion 中共享时间轴；中文为主要阅读层，英文作为字号适当的次级阅读层。按短句显形、关键词强调与稳定落定组织字效，双语行距和安全区按真实导出检查。句级估时、字级对齐和完整听校分别记录；有配音改词时同步更新字幕与翻译。用户要求显示代称时维护中英文对应词表，只改约定的显示层，不静默改原口述或游戏UI；用户举例不等于平台官方统一违禁词，不保证替换后必过审。

用户要求常驻BGM时，它应贯穿约定正文并在实际混音中可感知，开尾淡入淡出，必要的留白有明确表达目的；不能只在片头/转场出现，或因怕盖人声把整片压到听不见。保留独立音乐支路与覆盖区间，在开头、中段、结尾的实际导出中比较含人声/纯音乐听感，再调整编配、频段和适度避让。整片LUFS、音轨存在或非静音仅证明信号，不证明BGM听得见；收到“没有BGM”的反馈要先检查导出支路和实际存在感，不能拿源码中有音乐反驳。讲解仍保持清楚。可见倒计时与可听提示音使用相同的起点、秒数和揭晓点。
