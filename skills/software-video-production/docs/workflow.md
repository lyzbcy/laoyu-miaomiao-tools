# 制作流程与项目组织

现状：已有镜头、剪辑与合成执行入口；以下为创作到交付的生产主线，不宣称一键生成优质成片或已验证传播效果。表达形式按内容选择。
维护人：当前制作 Agent。
最后更新：2026-11-02。

## 先确定事实

- 找到实际文件；路径和文件名以文件系统为准。
- 查时长、方向、旋转、HDR、音轨；看完整事件、听声音。只有抽帧时记录验证限制。
- 写源时间表：什么时候播放、切换，哪块屏幕是本机/投影/录屏；证据和未知分别写。
- 核实产品名、获取渠道、看点和传播限制。不为拍片改软件。
- 标出文档、聊天、账号、内部链接、文件名等隐私，以及不能遮挡的功能证据。

“少了一个窗口”可能来自页面切换、镜头移动或投影关系，不能直接推断软件功能。

## 建议目录

```text
<项目>/
├── SKILL.md                 接手入口和当前交付
├── docs/
│   ├── agent.md             导航
│   ├── brief.md             当次目标与约束
│   ├── production.md        素材事实、创意和时间轴
│   └── review.md            用户原话、修订与结果
├── source/或原片索引         原片位置、元信息与哈希
├── work/                    缓存、遮罩坐标、中间音频
├── output/vN/               成片、封面、文案与检查
└── scripts/                 项目重建脚本
```

已有项目沿用既有结构，补入口即可，不必移动大量素材。原片在桌面等位置可只登记路径和哈希。用户指定盘位时，将新增工程、渲染、TEMP和缓存都放入该盘项目目录，复用现有依赖不等于要重新安装到系统盘。work中分清唯一输入与派生物：记录生成脚本、上游依赖和可重建性，获准在线配音缓存不能因放在work就视为垃圾。

## 从素材到成片

生产主线是“观看理由 → 导演方案 → 代表段 → 全片生产 → 整体剪辑 → 交付与反馈”。每阶段交给下一阶段的是可使用的产物；下面的条件由 Agent 据实际内容判断，不默认逐阶段向用户请求批准。已有采用方案直接复用，局部修改只回到受影响阶段。

### 1. 从题材提炼一个值得看的变化

输入是当次任务、真实素材、目标观众及已有反馈。写清观众当下的困惑/欲望、看完能得到的具体变化、封面与首句承诺，以及正文中实际兑现它的段落。按[范例方法](exemplars.md)提取一个可迁移机制及对应源片段，避免只有风格词、参考链接或“吸引人”等评价。

输出沿用 `brief.md` 或制作文档中的简短创意主张。优先选择当前素材能兑现的看点；当开头尚未成立时比较少量短方案再选，不把整片做完后才决定讲什么。已采用的开头无需为流程重做。

### 2. 把内容写成导演方案，而不只是一篇旁白

按[制作 document](document.md)组织同一份生产依据，先形成内容骨架，再落到镜头：

- **内容递进**：每段承接什么未解问题，产生什么新信息/行动/感受，如何引出下一段。教学可走“直观例子→提问预测→操作揭晓→反例升级→抽象方法→独立练习→复习”，产品可走“具体困境→操作→真实结果→新用途”，生活片按真实事件和情绪变化组织；不把某种结构套到所有题材。
- **观众体验**：此段让人期待、思考、理解、惊讶还是放松；说明关注对象与可感知回报。快慢跟着任务难度和情绪变化走，互动和广告接在能自然承接的位置。没有新的信息或感受的重复段应重组。
- **视听表达**：决定什么交给画面、什么需要解释、角色为何行动、声音回应哪个事件。让人物与板书/产品/空间发生关系，不把每句旁白都包装成一页同构卡片。歌曲复习只回顾已讲清的内容。
- **视觉系统**：从当前授权素材确定角色、场景、字体层级、色彩、构图与镜头语言；同一任务的连续过程保持空间关系，关键转折才改变景别或位置。以少量能在当前渲染器还原的关键帧明确质感，再扩展；需要全片关键帧审阅时覆盖完整内容路线。

分镜中至少能找到：稳定 shot id、段落意图、实际口播/屏幕文字、画面状态与变化、角色动作、声音事件及其时间依据、素材引用、所用渲染路径。 已启用系列或本轮要求互动、常驻BGM/更丰富音效时，在本份方案提前安排回顾位置、各项互动出现时刻、音乐覆盖与事件音效清单；交片按[五项内容复核](delivery.md#交片前的五项内容复核)逐项找实际兑现，缺素材或缺声音不能静默落下。已有 storyboard/EDL 支持这些信息就直接复用，不强换格式；源区间剪辑按[editing](editing.md)保留可回滚映射。静态布局、人物帧、事件时刻与音频各有来源，合成时从同一分镜引用，避免多处手抄时长。

此阶段成立的标准是能回答“观众为何接着看、为何能看懂、这个镜头为何这样拍”。只有完整台词、视觉形容词或镜头数量，还不能进入全片批量生产。

### 3. 用有声代表段验证整条链路

选择最能决定本片质量的段落，例如首次认知回报、最复杂推导、情绪转折或重要产品操作；不是只验证容易做的入场。按[动效案例](advanced-cases.md)选型，按[自研集成](integration.md)或[原版上游](upstream.md)选择已接通能力。真实素材先脱敏；合成demo只验证技术能力。

代表段应串起真实可用素材、实际口播/所选音乐、字幕、角色/信息动效、事件音与最终导出。约8–12秒可以作初步长度参考，完整事件需要更长就保留。正常速度与选定参考对照：是否在期待中及时得到回报，信息能否读懂，动作是否帮助表达，声音是否让变化更有感受。

输出一个可播放样段及本次选择的理由。失败时定位是看点、脚本、设计、素材能力还是渲染问题，回到对应阶段修改；不为掩盖问题继续加特效或扩展全片。关键音源/角色能力缺失时，说明它影响哪些段落，先推进不依赖它的部分，粗剪占位不当成已验证风格。

### 4. 锁定表达后批量生产

把代表段中成立的视觉系统、镜头组件、动作语汇与声音关系用于同一片子；变化来自内容需求，不是重复同一转场。按已确认文案合成或复用匹配的配音，实测时长后安排时间线、字幕、动作和事件声；实际演唱音源按[music-generation](music-generation.md)取得并核对，再编排复习段。图像资产按任务使用可用生图工具；真实功能由真实画面承载。

复用有依据的素材/组件/缓存，只重做受变更影响的内容：文案变化需核对对应音频、字幕和镜头时长；重排后重算事件与后续时间，不把旧的绝对秒数直接搬入新片。输出可重建工程、素材索引、全片有声粗剪及尚未完成项。工具限制和步骤证据按[集成](integration.md)、[账本](#步骤账本与恢复)记录，不以一个脚本启动成功代替流水线完成。

### 5. 从整片观看体验做编辑

原速检查开头兑现、内容衔接、中段重复、认知/情绪转折与结尾回报；长片不能仅凭每镜局部都合格判定整体好看。先删重组无新增价值的段落，再调整停顿、画面与声音密度；保留看懂操作、读词、反应和自主思考所需时间。不为压固定时长全片提速。

封面在主创意确定后可并行制作，围绕同一个具体看点；片尾广告承接观众已理解的用途，以真实结果与明确获取方式收束。二者都参与内容表达，不在最后机械追加。片中约定的系列回顾、署名和推广仍保留当次约束。

输出修订后的具体成片版本。按[交付](delivery.md)分开检查技术、事实/隐私、实际视听与手机阅读，逐切点核对语义、声音、字幕、遮罩和源边界，最后完整解码；能力不足时明确未看的范围，不靠书面自评放行。

### 6. 交付后让流水线获得反馈

交付成片、封面与重建入口，记录采用范围，按[运行小结](run-summary.md)收尾。复盘优先判断哪一阶段的输入或方法让成片变好/返工：有证据的创作选择更新已有规则，可复用的技术实现接入现有执行链，项目参数留项目，防错项回到相应验收段。

可复用资产应同时说明用途、输入、来源、适用边界与采用/验证状态，避免只有一堆效果文件。将用户认可和平台表现分别记录；尚无数据时保留内容假设，不把一条采用结果写成爆款公式。未经请求不公开发行、上传素材或提交PR。

## 修订纪律

新反馈补充当前任务，不丢掉先前约束。每版写清变化与来源。删除片头可精确裁切，不必重做整条；检查首帧、首句、字幕、事件音效与节拍是否仍同步。

## 步骤账本与恢复

完整新片先初始化项目账本，不依赖长对话记忆：

```powershell
python scripts/workflow_audit.py init WORKFLOW.json --series --image-cover
python scripts/workflow_audit.py record WORKFLOW.json --step hook --evidence HOOK_REVIEW.md
python scripts/workflow_audit.py record WORKFLOW.json --step audio --blocked "等待指定音源"
python scripts/workflow_audit.py audit WORKFLOW.json
```

两个flag仅在本次启用系列、明确要求生图封面时加入。固定阶段覆盖需求、开头、分镜、动效选型、代表动效、音频、封面、技术验收、交接或收尾；条件阶段额外检查上期依据与生图产物。record保存真实证据文件及SHA256，不支持无证据勾done；audit在未完成、受阻、证据缺失/变化时返回非零退出码。证据内容与实际验收范围仍由Agent核对，任意文件存在不代表内容正确。交接发布时带同一账本，待办不伪装为已通过。

封面先写清采用生成插画、真实截图还是代码排版的理由。用户要求生图时实际调用可用生图工具并记录提示词、参考图角色和输出；不能把代码海报或视频抽帧称为生图。未要求时按内容选合适方式，已有合格封面不重复生成。封面生图不意味着视频也要接图生视频；两者分别决策。个人项目偏好留在项目约定，不升格为所有用户默认。

账本不是自动执行器。开工把本次适用步骤列出；已有证据先核对并复用；交付前audit，缺证据则补做或如实报告待办。不要为了变绿补写虚构验收。

宣传封面是静态图，能直接用生图成品；视频讲解关键帧仍须证明当前渲染管线能还原，不能把二者的限制混用。

workflow_audit的complete同时要求制作与closeout账本通过；production_complete只表示制作证据已覆盖，不能代替PR、归档和清理完成。旧账本没有closeout_ledger时会报告缺失，不自动补成绿灯。
