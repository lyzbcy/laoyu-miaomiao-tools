# 制作流程与项目组织

现状：首例实拍流程跑通；表达形式不固定。
维护人：当前制作 Agent。
最后更新：2026-10-15。

## 先确定事实

- 找到实际文件；路径和文件名以文件系统为准。
- 查时长、方向、旋转、HDR、音轨；看完整事件、听声音。只有抽帧时记录验证限制。
- 写源时间表：什么时候播放、切换，哪块屏幕是本机/投影/录屏；证据和未知分别写。
- 核实产品名、获取渠道、看点和传播限制。不为拍片改软件。
- 标出文档、聊天、账号、内部链接、文件名等隐私，以及不能遮挡的功能证据。

“少了一个窗口”可能来自页面切换、镜头移动或投影关系，不能直接推断软件功能。

## 建议目录

```text
<项目>/
├── SKILL.md                 接手入口和当前交付
├── docs/
│   ├── agent.md             导航
│   ├── brief.md             当次目标与约束
│   ├── production.md        素材事实、创意和时间轴
│   └── review.md            用户原话、修订与结果
├── source/或原片索引         原片位置、元信息与哈希
├── work/                    缓存、遮罩坐标、中间音频
├── output/vN/               成片、封面、文案与检查
└── scripts/                 项目重建脚本
```

已有项目沿用既有结构，补入口即可，不必移动大量素材。原片在桌面等位置可只登记路径和哈希。

## 从素材到成片

1. 写观众视角的一句看点；按[范例流程](exemplars.md)选择主参考，播放对应片段，将参考ID、源秒数、动作机制与本片迁移方式记到production。不要只留链接或模仿配色，不把生视频模型的画质当剪辑能力。
2. 时间轴记录源ID/哈希、源入出点、画面事件、事实、口播、动效、声音和遮罩；在需要强调的转折处判断信息和视线是否拥挤，标明继续推进、减轻干扰或等待结果的理由，不套固定能量曲线。区分实拍与创意示意。按[editing](editing.md)将拟删区间与批准分开，保留可回滚EDL、剪后字级映射和语义分镜；脚本不自动代替语义听审。
3. 需要可执行链时按[自研集成](integration.md)或[原版上游](upstream.md)选择已验证的能力；仅在素材与任务需要时调用转写或字级剪辑。只授权合成测试时使用demo，不读取真实原片。正常制作尽早用自己的原素材做约8–12秒代表预览，包含真实操作、有意义的动效和关键事件声音，与选定参考正常速度对照，判断节奏、可读性与动作是否成立后再扩展。代表段按本片风险选，不能只检验开头；担心中段乏味时检验该转折，并对比直接推进的处理，避免人为制造等待。不默认逐段请求用户批准；缺核心信息或已约定审批时再等待。
4. 隐私处理先于公开展示，再裁切、推近和合成。改构图后重新检查。
5. 配音/字幕用真实时间戳，改文案使对应缓存失效。节奏可以由动作、音乐或音效主导，不固定逐句卡片。
6. 完整片分别检查媒体、功能/隐私、视听表现和手机阅读；逐切点看前后窗口与源裁剪边界，核对语义保留、音画接缝、字幕和遮罩，再完整解码。检查命令与能力范围见[editing](editing.md)。
7. 交付具体版本，收录用户反馈，更新案例。

## 修订纪律

新反馈补充当前任务，不丢掉先前约束。每版写清变化与来源。删除片头可精确裁切，不必重做整条；检查首帧、首句、字幕、事件音效与节拍是否仍同步。

## 步骤账本与恢复

完整新片先初始化项目账本，不依赖长对话记忆：

```powershell
python scripts/workflow_audit.py init WORKFLOW.json --series --image-cover
python scripts/workflow_audit.py record WORKFLOW.json --step hook --evidence HOOK_REVIEW.md
python scripts/workflow_audit.py record WORKFLOW.json --step audio --blocked "等待指定音源"
python scripts/workflow_audit.py audit WORKFLOW.json
```

两个flag仅在本次启用系列、明确要求生图封面时加入。固定阶段覆盖需求、开头、分镜、动效选型、代表动效、音频、封面、技术验收、交接或收尾；条件阶段额外检查上期依据与生图产物。record保存真实证据文件及SHA256，不支持无证据勾done；audit在未完成、受阻、证据缺失/变化时返回非零退出码。证据内容与实际验收范围仍由Agent核对，任意文件存在不代表内容正确。交接发布时带同一账本，待办不伪装为已通过。

封面先写清采用生成插画、真实截图还是代码排版的理由。用户要求生图时实际调用可用生图工具并记录提示词、参考图角色和输出；不能把代码海报或视频抽帧称为生图。未要求时按内容选合适方式，已有合格封面不重复生成。封面生图不意味着视频也要接图生视频；两者分别决策。个人项目偏好留在项目约定，不升格为所有用户默认。

账本不是自动执行器。开工把本次适用步骤列出；已有证据先核对并复用；交付前audit，缺证据则补做或如实报告待办。不要为了变绿补写虚构验收。

宣传封面是静态图，能直接用生图成品；视频讲解关键帧仍须证明当前渲染管线能还原，不能把二者的限制混用。
