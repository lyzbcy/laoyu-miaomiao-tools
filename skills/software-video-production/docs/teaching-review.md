# 教学示例台与连续讲解

用于用户要求先审讲解、采用角色辅助教学或准备系列知识视频时。先读取项目 SKILL.md 或作者配置，沿用已确认的人物、字幕语言、音源库和评审要求；这些个人选择不升格为所有视频的默认值。

## 先交可评的代表段

用户要求关键帧审核台时，覆盖整集的教学推进，不只挑几张美术好看的画面。关键帧来自同一可重建渲染源；涉及来访、读取、返回、状态切换或预测揭晓的段落，补动作前中后或条件对照帧，防止提前显示答案、原件消失或把旧页面保留误讲成新访问成功。逐帧与整集意见分开保存，坐标批注绑定画面版本和变体；放大时按实际图像区域映射坐标，不能把黑边当成画面。静帧、动作测试、生视频片头、配音及成片分别标状态。

示例台至少能播放实际渲染样片、按段跳转、查看对应讲解与译文、留时间标记、评分和评语，并能保存及导出结果。未评分保持空值，不能预填高分或把技术通过记为用户采用。评分绑定版本和稳定段落 ID；更换口播或重排时间线后，不把旧时间码直接套到新片。普通项目无需为了流程固定做同样数量的样段。

用户明确要求先评审时，先完成这一步再扩展全片。代表段覆盖决定理解质量的推导或因果，不能只有角色入场。口播、片头、音乐、字幕、角色能力和演示分别标完成状态；缺配音时可以交文字节奏预览，但不能称为有声讲解验收。已有作者自写口播偏好时，候选示例措辞标待评，不擅自批量扩写成最终作者口播。

## 将滑梯效应落实为承接

入门课先明确观众起点和一个可以预测、操作、观察的学习结果。先给具体任务及可观察差异，再按需要引入名称；后一个解释不能依赖尚未教过的概念。不要把专家排错清单或术语关系图当作入门路径。首次教学允许围绕同一概念做必要对照和迁移，不能因追求密度把它们全删掉；验收看学习者能否预测换一个条件后的结果，不用“懂了吗”或背定义代替。用户否定教案时，先重排任务、先修关系和理解检查，再做可评教案样段，避免在尚未成立的讲解上继续投入完整渲染。

由浅入深必须写出“深”的落点。依据源材料登记原章节、所需先修知识、本集新增的专业判断、实际证据和证据边界；类比之后接正式概念、真实输出的读法、可复现操作及换条件后的判断。面向更广的观众时补入门台阶，不把原材料的专业目标删成只剩生活比喻。系列保留源材料覆盖表，注明本集教到、后续承接及尚未覆盖的部分；不能用多集反复解释同一比喻充当进阶。每集选一条因果链深入，避免把整本专业手册压成术语报菜名。

为每段记录“观众现在的问题 → 本段给的具体回报 → 回报自然产生的下一问”。句子先让人读懂再引出新信息；前一问应得到足够回答，再升级一个变量。删除重复的开场、总结和术语预告，保留预测、观察、读屏所需时间。避免持续卖关子、故意省掉必要解释，或把特效密度、快语速当成滑梯效应。该结构是编辑方法，未有平台数据时不宣称它保证流量或学习效果。

## 日常角色片头的条件分支

用户要求开头建立学习期待时，第一屏交代具体观看收益，例如本集看完能解释、判断或完成什么；可结合实际时长和零起点范围，但承诺必须由正文兑现。角色日常可以保留并与收益字幕并行，不让观众先看完一整段无关日常才知道在学什么。标题承诺不等于让正文提前堆术语；不能把“认识服务器的工作”夸成“一次学会部署与运维”。

当用户明确采用独立于教学的角色日常片头时，允许先呈现日常、再通过视线、道具、动作或一句过渡进入本集；不要用“教学必须第一句点题”的旧规则否决用户选择，也不必把日常硬凑成知识类比。片头长度、角色和视频模型按当次要求或作者配置。

生成参数与提示词分开；优先使用实际上传的角色参考锁定身份，避免重复外观描述。记录输入哈希、实际模型、费用状态和输出。既有生成片段只能标复用或风格占位，图片平移不能冒充生视频，失败时不能宣称已生成。配额、登录或验证码按工具实际约束处理，不绕过限制、不自动付费。

## 信息动效与双语字幕

用户反馈信息密度低时，先数每段新增的状态、因果、证据或可迁移边界，删掉没有新信息的反复提问与长等待；不要只提高语速、同时塞更多字。用户明确要求更快且持续推进时，常态口播采用更紧凑的短句和衔接，按同音色基准试听提速；不用每句后留白制造所谓节奏。仅在重大判断翻转或核心揭晓前安排有目的的短暂收静，随后让重点、画面和声音同步兑现，避免每个小知识点都静音再炸响。记录实际语速、停顿位置和用途；候选提速比例不等于已试听通过。可以用同一个例子完成操作、失败、证据和恢复，让画面变化与解释互补。关键命令与字幕可跨口播保留供阅读，不靠把所有字同时塞进屏幕维持密度。仍需用实际样片检验观众是否跟得上，概念数和秒数不是学习效果指标。

用户要求立体世界时，把解释对象放进有一致位置、尺度、遮挡和前中后景的空间；用对象行动、状态变化、请求路径和连续镜头解释因果。避免始终在同一平面轮播文字卡。生成背景只负责场景，不把关键状态或标签烘焙在背景里；独立对象承担可变事实，字幕保持可读。CSS 3D/2.5D 合成、完整三维模型、网格角色动作分开命名，不因有透视背景就宣称真实三维世界已实现。

角色必须按本轮指定身份复用。作者说猫装本人或已验收的网格/Live2D角色时，不以写实小奶猫头像替代；复用网格动作先检查实际帧、透明通道与支持的动作范围，不能把立绘平移称为身体变形或逐字口型。个人角色选择和生图背景要求记录在作者配置。

沿现有 Remotion 案例和帧驱动时间轴选择空间推进、蒙版短语、状态链、路径跟随、局部聚焦或语义转场；说明每个效果帮助看懂什么。角色参与追问、预测和解释，不能只靠全程漂浮代替反应。重要信息落定可读，按画幅核查最长字幕、关键命令、运动中间帧及首尾。

用户明确要求“每一句都有强烈变化”时，逐句建立稳定ID与视听事件映射，覆盖所有口播句，不以段首一个转场替代后续各句变化。每句至少安排一种显著且与语义相合的变化，例如推拉镜头、构图或景别改变、关键词字幕动画、状态特效、音色或声场变化、背景切换、事件音效；记录触发词、前后状态及音效落点。微弱漂浮或普通字幕换字不能单独算已满足强变化。长句内含多个判断时，按语义节点继续推进。声音可丰富轮换，强变化不要求每句都堆满全部手段或提高音量；保留技术证据和双语字幕的可读性。音色变化是可用手段，基础音色仍按作者配置。逐句标注与实际成片验收分开，须试听并检查句首、变化峰值、落定画面；没有渲染不得声称已经实现。

双语要求进入第一份完整样片；中文与对应译文共享语义段 ID 和时间范围，中文主层、英文次层，不能漏译否定词或条件。估时字幕与实际音频对齐分别记录。配音不可用时如实停在视觉样片，不静默换声。

## 先用已打标的音乐与音效

作者指定已有打标库时，先读实际库和原备注，再按场景、情绪、剧情和事件匹配；音效也走这一顺序，不能只优先 BGM。记录音源 ID、版本、标签、备注、可用文件、源入出点和混音落点。没有适合项或文件缺失才补充其他音源，并写明原因。打标不等于已试听合适或已获跨平台许可。

## 反馈回流

作者指出标题费力或动作贴片粗糙时，先解决对比与语义：把长标题缩成当前问题，落在稳定的高对比阅读面；让请求沿实际方向到达、读取在源对象上发生、状态开关与结果联动。更华丽不是换字体、加光效的同义词。人物、字幕、动效分别能解释什么要在实际片段核对，不能用组件名称证明质感已通过。

用户指定高频注意力检查（如每1.5秒）时，按该间隔建立审核点，写明此刻观众在等什么、画面/解释如何推进或兑现、下一问从何而来、哪里可能拖慢。间隔是检查频率，不是强制切镜或新增概念的频率；稳定阅读与预测思考可以持续，但必须有明确目的。用已有认识引出可回答的新问题，先给局部回报再推进，不能持续拖欠答案。计划表只证明设计已登记，实速样片与用户理解反馈另验，不宣称能保证留存或“划不走”。

制作日志随执行追加时间、动作、实际结果、证据路径/哈希和未完成项；失败也留记录，不在交付前补写成已执行。将反复出现的采集、冻结、天数计算、时间线插入与检查点生成固化成可重复脚本，重跑不得重复插入段落，也不覆盖作者评分。保留原始反馈、制作假设、技术检查和实测效果的区别。

用户已明确授权维护 skill 时，把可迁移方法写入本页等相关模块，角色原图、私有曲库路径、账号和本次原话留项目或私人作者配置。新确认偏好可在个人配置复用，但不得写成用户已经采用某条候选片段。维护本机 skill 不等于公开发版或提交 PR。
