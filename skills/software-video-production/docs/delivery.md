# 交付与分层验收

现状：媒体检查可自动执行；审美与用户认可独立记录。严格流程交付附步骤账本：实际调用、分镜/EDL、字幕与音频处理、动效组件、时间线/切点检查、渲染验收及各自证据。原版上游、自研组件和手工处理按实记录；没有执行的步骤不能靠工具名称或模板勾选补齐。
维护人：当前制作 Agent。
最后更新：2026-10-28。

## 分开记录的结论

1. 技术：可完整解码，方向、尺寸、音轨、时长正确，无非预期坏帧或截断。
2. 内容/隐私：事实与字幕对应，工作内容遮住，功能变化未被遮坏，无新增承诺。
3. 视听自检：正常速度看过/听过什么，手机阅读和风格结果；能力有限时注明只抽帧或未完整试听。
4. 用户评价：原话、对应版本与真实等级。交付或技术通过不能代替用户认可。
5. 发布表现：来源、采集时间、作品ID与形态、发布龄期、播放/曝光、2秒跳出、5秒到达、平均观看及整片完播（若有）。审美认可不代替观看表现；5秒指标、平均观看和全片时长各有含义。3/5秒跳出率须取对应作品的平台行为数据；缺数据时只给0–3/0–5秒逐镜头证据、划走风险与修复建议，不能编百分比或把代理判断称作实测。

## 媒体工具

```powershell
python scripts/media_check.py "<原片>" --mode inspect --output "<项目>\work\source-media.json"
python scripts/media_check.py "<成片>" --mode verify --output "<输出目录>\media-check.json"
```

`inspect` 只读元信息；`verify` 增加完整解码，有音轨时测响度。`technical_pass` 仅指存在视频流且完整解码成功，不验证事实、审美或打码。

抖音常用 1080×1920、H.264/AAC，但按任务/平台选，不强制同一时长、帧率和画幅。

## 成片检查

| 维度 | 所需证据 |
| --- | --- |
| 留人 | 关注对象、待解问题、已见回报与后续期待；约3秒、5秒是观察点，原速核对兑现，不要求5秒揭完完整谜底 |
| 功能 | 动作结果先后合理，变化看清 |
| 关系 | 本机、投影、截图、创意示意没有误称 |
| 创意 | 不是固定大字/卡片换页，创意与产品有关 |
| 运动 | 列实际时间点、信息关系和表达作用，入场后有可读落定；数据尺度与最终值准确，不用循环或数量证明丰富 |
| 节奏 | 重点是否接得住，主线与期待是否持续；减量是否有用，空档能否删除；无停顿的紧凑表达也可通过，不按动静次数打分 |
| 声音 | 清晰自然，音画响应，口令按要求不读 |
| 隐私 | 转场/放大不漏字，界面关系仍可读 |
| 手机 | 首版完整片包含约定语言的完整字幕，显示词表与翻译一致；最长句、框样式、字幕口令和关键UI在手机安全区可读 |
| 获取 | 渠道、产品名、口令一致，链接符合当次约束 |

“像 PPT/HTML PPT”单独检查。即使特效、配乐、字幕都有，也要看整个视频的画面组织和叙事。

逐切点导出前后窗口并核对语义、声音、字幕、隐私遮罩和口型，范围与命令见[editing](editing.md)。抽帧、解码、字级算术和非静音检查不代替真人听审；3/5秒只作启发式对抗检查。同素材A/B与实际成本、返工记录留项目，未实跑不宣称收益。

## 交付

完整交付后须按[运行小结与经验贡献](run-summary.md)输出并保存运行小结：用户问题、逐版修改与数量、最终实现、实际验收和未知、经验价值。盘点本项目旧版本和实际占用，数量多或体积明显偏大时附清理清单、保留项及预计释放空间，主动询问是否清理。用户确认最终交付或本轮结束后，只有经验值得沉淀才附上脱敏草案并询问是否愿意提交PR，合入后按意愿加入skill贡献者名单。旧版本清理与PR提交分别授权；用户答复后按运行小结的创建清单清理本次临时贡献包，无需另问清理授权；未完成或仅中间预览不冒充完整交付，不重复邀约。

用户采用后要求继续多平台发布时，按运行小结中的交接约定继续同一任务；由发布阶段结束后合并汇总，制作阶段不提前发整套最终邀约。平台仍待查就先汇报阶段状态，不把上传或提交当公开可见，也不清理后续需要的文件。

主文件是明确版本的 MP4，按用户分发平台同时考虑独立封面、文案、字幕、口令。重建脚本、清单、时间轴和媒体检查留项目，别让用户猜哪个中间文件可用。

封面比例与视频比例分开。用户要求横竖两版时重新排版，不拉伸脸或字体；检查实际文件宽高，不能仅凭生成提示词宣布比例正确。大字和人脸避免被裁切，JPG便于上传，PNG保留原图；建议用途与来源放交付说明，实时入口以上传预览为准。使用生成素材参考真实表情时，重绘结果不能声称原PNG逐像素复制。

封面单独解决“为什么点开”：按内容选一个问题、利益点或人物反差，别把功能说明页缩成海报。生活情境片可用正面大表情与一句悬念，软件教程可突出真实结果；产品署名居次。多卖点、整页UI、口令和装饰不同时堆满。先看手机缩略图能否认出表情并读懂主句，再看各平台真实裁切。成片采用后仍可单独否定封面；重做与上传成功不等于新封面已获认可或CTR提升。

生成或修改含人物的封面，除了脸和文字，还检查肩→上臂→肘→前臂→手腕的连接、长度、朝向与遮挡。修改手指的目标位置时，同时重审整条手臂和身体姿态；局部指向正确仍可能形成异常长臂、错接肩膀或多肢。姿态无法自然实现时，调整人物与目标的距离、重做完整姿态，或用视线和图形强调承接指示，不硬拉长肢体。自然放手只是可选修法，不作为所有封面的固定构图。定向修图后再核对文字、数字、角色身份和画幅，避免修好局部又破坏原有信息。

交付链接指向最新版本，可打开结果。封面从处理过隐私的素材取图。文件交付不等于授权平台发布、发消息、上传原片。

用户给合格但仍有风格缺口，就如实归档；不能包装成优秀标杆，也不丢掉下次改进意见。

## 原画包与原生对照

Release 附件与 Source code ZIP 分开核验；后者可能没有原 MOV。记录附件名、实际大小、SHA256 和最新说明版本。原生 UI/手机截图在 4K 画布中不得超过自身像素尺寸。

画质对照按时间轴与实际 PTS 找同源帧，保存 100% 同区域并排图和选帧方法，不拿不同表情、帧或缩放比较。短录屏 EOF、下一张 UI 接入和隐私遮罩都要检查边界帧；必要时保持最后一帧，避免一帧闪空。保持 EOF 只适用于该元素仍应显示的时段。

环境不支持完整听审时，记录实际检查范围和原因；抽帧、ASR、解码与响度不能写成耳听通过。

## 截图获取引导的证据边界

观众可将清楚的片尾指令截图直接给 Agent，不必要求手打。要求在当前页面给prompt时，直接使用实际页面，不换成无关示意；核实产品名、作者、可检索仓库与下载入口，实际导出中留足截图阅读时间。片尾产品名和助理名要用用户确认过的准确写法。用户给出的操作截图作为依据时，记录其可见步骤：识图、搜索、下载安装包、启动安装，与安装完成、产品配置和运行成功分开。带网址的依据截图在要求无网址的视频中不直接插入。

工程提供相对路径脚本与实际媒体清单；包含原片时说明用途，未包含时写清放置路径、大小与 SHA256。

启用系列记录时，另检查天数的首发日依据、当地日期、跨镜头位置，及上期作品ID/封面/指标/采集时刻是否一致；只显示已取得指标，不能用账号净增替代作品涨粉。混合素材须检查常驻层贯穿真实录屏与EOF，详见[series](series.md)。

## 交片前的五项内容复核

按用户要求和已启用系列逐项记录“已实现＋时间点/产物”“不适用＋原因”或“待补＋缺口”，在制作document/分镜或交付检查中保存，交给现有workflow的hook、series_context、audio和media_qa证据。不能用全片解码通过覆盖这些内容缺失。

| 复核项 | 检查实际导出，而不只看计划 |
| --- | --- |
| 上期回顾 | 同系列真实上一期，标题/ID/封面/指标同源，显示采集时间；历史指标不冒充实时。已有系列却尚未查到，属于缺口而非自动不适用 |
| 点赞收藏评论关注 | 按本次要求逐项查找实际口播或可读画面，评论有具体可回答的问题，关注说明后续价值；不拿一句“支持”替代四项 |
| 开头观看理由 | 首帧与首句可识别目标观众、本期任务和观看收益，再核对0–3秒/3–5秒的具体事件与首份回报；“不明所以”先补语境，不以题内冲突、旧采用或特效数量放行 |
| 常驻BGM | 核对约定段落的覆盖、开中尾实际音乐存在感与口播可懂度，不能只证明音轨存在或文件非静音 |
| 事件音效 | 对照动作时间点检查缺失、同步和抢话；连续动作、冲突、揭晓等有对应反馈，不以“有几个音效文件”判定充分 |

实际听过、仅作信号检测、只抽帧分别记录。无法完整耳听时如实保留限制，不把五项书面打勾当作主观视听通过。用户认可和平台留存仍独立记录。

用户要求品牌与往期作品片尾时，另核对真实素材绑定、实际滚动、约定时长、首中尾可读性与口播/双语字幕；它属于本片交付内容，不因四项互动已有而省略。

## 网页预览必须能拖动进度

本地视频预览使用支持HTTP字节Range的服务，可运行 `python scripts/serve_preview.py --directory <交付目录> --port 8891`。普通静态服务返回整文件200或仅设置video.currentTime成功，不足以验收拖动；检查请求Range得到206、Content-Range与Accept-Ranges: bytes，并用实际鼠标/触摸操作进度条，跳到尚未缓冲的后段再拖回前段，等待seeked与可播放帧并核对时间。保留原生controls，必要时给明确可拖的进度控件。章节按钮跳转、能从头播放或元信息可读，不能代替此项检查。

重启预览服务前核对原进程路径、端口与服务目录，只替换本任务的服务；不结束其他项目进程。把服务启动方式和拖动结果随工程保存，避免下次又退回不支持Range的服务器。

### 从真实对象做极简生图封面

软件宣传封面可先提取最有辨识度的真实对象，用生图将它放大成为主体，背景减到只提供衬托。标题提出与对象直接相关、正文能兑现的好奇问题；补充信息只保留解释对象用途所需的一句。多个对象先保留身份、数量、对应标签与关系，不用一堆功能文案挤掉主体。

用户指定生图时实际调用生图并保存提示词、参考角色与结果；竖版与横版按构图分别生成/编辑，不默认中心裁切能保留所有对象和标题。对各比例检查手机缩略图中的对象辨识度、文字/数字与安全区，上传后仍核对实际裁切。封面允许插画化，但不能把生成UI、比例或效果当软件实测证据。

回流时区分用户已指定/认可的方向、实际生成与裁切检查、发布后的点击或留存数据。只有前两项时记录为设计方法或候选案例，不声称已经提高点击率。个人角色与具体双球方案留在私人项目配置。

若系列已约定双语或用户要求Remotion动效，完整首版同时核对标题、细节、CTA、回顾等实际可读文字的双语，以及正文中帮助理解对象/因果的真实动效；仅片尾一个Remotion卡片不算正文动效需求已兑现。
