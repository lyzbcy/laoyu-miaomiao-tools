# 让画面承担叙事

## 钩子与信息分配

开场先给问题、异常或有吸引力的结果，再解释产品。比较原片最强瞬间与拟新片头；署名不抢观看理由。软件演示前段应看懂对象、动作和反馈。

先写角色此刻要做什么、遇到什么阻碍、操作后有什么改变，再决定字幕或口播。已经由画面表达的内容不重复解释；真实功能存在理解缺口时补讲解，不能用长音乐空段拖过去。RPG心声用于当下意图与反应，例如回家疲劳→关闭手机蓝牙→连接电脑，少写场外解说式“捞鱼这边”。

## 构图与动作

主景交代空间和操作关系，特写承担表情或关键动作；按叙事改变景别、视线和人物关系。换底色、同一站位换舞步不等于换画面。固定卡片、轻推拉和转场堆叠仍可能像PPT。

每个动作有起因、过程与落定。精选表情也需要探头、回看、蓄力、反应和停顿；不让所有PNG持续正弦浮动。RPG打字时可局部点头，配合背景轻扰动；留白时稳定。运动要帮助注意、情绪或理解，事件密度不等于持续震屏。

像素或游戏段先做一个可读的完整场景：目标→行动→交互→反馈→回接实拍。图标漂移和闪灯不足以构成游戏表演。软件结果仍使用真实证据。

## 文字与光绘

先分清场景提示、角色心声、歌词、操作指示和获取口令各自职责，避免同句重复占位。按手机观看尺寸检查普通字、换行、特写与平台安全区，不能只依据工程字号。

字效响应语义：压扁、熄灭、弹回、绕物等要有触发与可读落点。捞鱼系列可参考已认可的光绘与GLM发光字：实心字保证识别，外层柔光塑造质感，描线/流光/显形服务登场或揭晓；不把模糊辉光当字形，不全片持续发光。需要具体素材时读[复盘依据](lessons.md)与[复盘依据](lessons.md)。

歌词MV先核实实际演唱版本；普通唱词可读，重点词另做语义表演。字幕变形或遮挡时仍保留完整读词路径。生活情境片可把歌词置于右侧独立竖区，避免与心声、特写、下载指令争位；不强制所有片竖排。

## 参考与判断

按[exemplars](exemplars.md)选具体片段和源秒数，迁移一种能解决本片问题的做法，先做代表段落正常速度看听，再扩展。只看过画面不能宣称参考音乐踩点已验证。

静音看能否读懂变化；遮住标题是否仍在讲故事；正常速度是否疲于读字、重复或声音与动作分离。真实主体、桌面与操作细节保持清晰；截图口令可稳定停留。技术实现不决定观感优劣。

需追溯反馈时从[案例索引](lessons.md)选择；本次音乐/RPG的适用范围见[复盘依据](lessons.md)，不把句数、字号、每一两句换景等项目参数升为通用模板。
