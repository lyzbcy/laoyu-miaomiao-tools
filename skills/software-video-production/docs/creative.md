# 让画面承担叙事

## 开头给观看理由，后面及时兑现

首句与首帧一起设计：先找素材里能被认出、又值得追问的对象，再决定第一句话。面向特定工具用户时，让其正在做的任务或选择困境先被认出；歌词开头也须承担这个作用，不机械套“某某朋友注意了”。熟悉的桌面上出现虫子、收银台后换成不合常理的角色，都是先让观众认出正常部分，再改变一个关键常识；增加背景与动效的复杂度不能替代这个差异。以下按素材选一种，不要求每片凑齐。

| 素材里有什么 | 开头如何成立 | 第一次回报与承接 |
| --- | --- | --- |
| 眼前事物容易被误认，或已经出现异常结果 | 直接展示，让人验证“这是什么、怎么做到” | 异常本身已是小回报，再揭示原因或控制方式 |
| 一次操作有清楚的前后变化 | 待处理对象→触发动作→同一对象的结果 | 拍到变化后再演一个新交互；点按钮、显示“完成”不等于结果已被看见 |
| 目标与规则能一眼学会 | 让人预测能否接住、抵达，或下一次改变会怎样 | 一次成功/失败教会规则，随后只升级一个变量 |
| 熟悉的小事引发不寻常的反应 | 用物件和行动交代处境，紧接人物反应 | 一个结果出现后的平静、一次挫折后的反应，都可形成新疑问；不先讲道理 |
| 同一条件下有不同结果 | 先摆差异，再倒推如何形成 | 比较对象和依据清楚，后续解释仍围绕这项差异 |

如画面先出现容易误认的小窗，再及时揭示其真实用途，属于第一种。效果来自眼前判断与证据的衔接，不来自疑问句式；没有真实反差，就不硬写“你以为……其实……”。“为什么连接耳机这么麻烦？”只是需求提问，还需要具体设备、任务或操作变化支撑。不要用脱离素材的惊人承诺、假误导或持续卖关子留人。

检查四件事：第一眼看哪里、观众在预测什么、已经得到什么回报、接着还等什么。约3秒、5秒是观察点，不是统一剪点，也不要求完整谜底5秒揭完。第一份回报可以是异常、笑点、反应或一次状态变化；完整因果稍后解释。兑现之后改变任务、位置、规模或角色关系，让人继续预测；已有冲突后接回一般背景会重置开场，前3/5秒逐镜头核对是否推进具体事件，不重新介绍产品或只换底色。图文只能迁移首屏组织，不能虚构时间轴。

第一句话也包括无口播片的首条字幕或RPG心声；不要为强调首句而打断歌曲。用具体的小事替代“神器、强大、一定看到最后”等评价。产品名、工具名、开发耗时和角色名单放在观众已看懂这件事之后；对比片需要的模型署名从首帧清楚保留，同时让实际结果成为关注对象。

软件片优先试结果先行或一次操作的可见变化；生活片优先试具体处境与人物反应；喜剧/MV可让歌词重点词成为物件或规则，用词→动作→结果→反应完成小事件，随乐句进入新情境，保留完整读词路径。具体换景间隔遵从当前片子与用户反馈，不把某条参考的速度变成所有片的模板。

开头机制未定时比较两个短方案，再扩展；已采用的开头可沿用，不为走流程强制重做。只要脚本时，交出具体分镜、实际台词/屏幕文字与动作，不自动升级渲染；需要成片时再用真实素材做预览。时间轴合计正确不等于内容装得下：粗读对白和字幕，给换人接话、操作和反应留时间。拥挤时删短台词、减少回合或简化步骤，保留关键结果和笑点落定，不能先挤掉停顿、吞字或加速硬塞。未试读只记录粗估，不称已校时。

成片阶段用手机尺寸、正常速度连看前10秒并试听，检查兑现是否被慢打字、署名、前奏和解释挤后；字效、少口播和大幅动作不能降低关键信息到达速度。脚本可执行、实际视听与留存分别验收。

角色当下意图与反应可用短心声，已经由动作表达的不重复解说；真实操作仍有理解缺口时补讲解。把信息交给最合适的画面或声音，不把少说话变成少给观看理由。

## 构图与动作

主景交代空间和操作关系，特写承担表情或关键动作；按叙事改变景别、视线和人物关系。换底色、同一站位换舞步不等于换画面。固定卡片、轻推拉和转场堆叠仍可能像PPT。

每个动作有起因、过程与落定。精选表情也需要探头、回看、蓄力、反应和停顿；不让所有PNG持续正弦浮动。RPG打字时可局部点头，配合背景轻扰动；留白时稳定。运动要帮助注意、情绪或理解，事件密度不等于持续震屏。

像素或游戏段先做一个可读的完整场景：目标→行动→交互→反馈→回接实拍。图标漂移和闪灯不足以构成游戏表演。软件结果仍使用真实证据。

## 信息关系、动效与节奏

先确定观众要理解的关系，再选运动：差距用共用尺度的条形与差值，趋势按采样时间描绘并突出拐点，目标用实际值与目标线，因果或流程用对象移动和状态交接。缺少可比较数据时不强凑图表；原始截图复杂时可保留依据，另做准确、可读的局部解释。动效要交代从哪里到哪里、何时看清和何时结束，不以滑入、缩放或持续漂浮的数量证明丰富。

重点前是否减量由内容决定。默认先收起已讲完的元素、停止次要运动、减少新信息，让主线和期待继续；不自动黑屏、静音或留空。信息本来简洁时直接推进。只有确需阅读、反应、等待结果或强化转折时才考虑停顿，并明确观众在等待什么；没有期待、拖慢兑现的空档应缩短或删除。不设每片必有、固定位置、固定时长或周期性的动静模板。

需要减量时保留一个关注对象或未回答的问题，重点进入后给足理解时间，再决定是否恢复运动。画面、信息与声音可以分别收放，歌曲连续约束按[声音](audio.md)处理。对有疑虑的转折比较直接推进与减轻干扰两种短段：事实和核心观点相同，只改变竞争信息与必要停留；减量未帮助理解或力度，就选紧凑版本。该比较是项目判断，不是实测留存提升。

## 文字与光绘

先分清场景提示、角色心声、歌词、操作指示和获取口令各自职责，避免同句重复占位。按手机观看尺寸检查普通字、换行、特写与平台安全区，不能只依据工程字号。证据每屏只突出一项结论，原图复杂时用真实局部放大，留足从定位到读懂的停留；数量、申请完成、收到测评和录用是不同状态，不用快滚清单或多张小卡挤成一屏。

字效响应语义：压扁、熄灭、弹回、绕物等要有触发与可读落点。可参考经用户认可的光绘与发光字：实心字保证识别，外层柔光塑造质感，描线/流光/显形服务登场或揭晓；不把模糊辉光当字形，不全片持续发光。适用范围见[复盘依据](lessons.md)。

歌词MV先核实实际演唱版本；普通唱词可读，重点词另做语义表演。字幕变形或遮挡时仍保留完整读词路径。生活情境片可把歌词置于右侧独立竖区，避免与心声、特写、下载指令争位；不强制所有片竖排。

## 真实复述与自然转入

生活vlog先回源核对事件顺序与情绪起因，保留“发生了什么→为什么失落/高兴→采取什么行动”的必要铺垫，再接奖励或工具。复述他人提示要标清“我的复述”，放回真实发生的任务语境，不剪成伪造现场对话。引用外部视频/文章时用核实的真实封面与条目；用户指定看板和封面时按对应条目ID、标题和原图匹配，保留来源及哈希，不用相似海报替代。公开帖子图保留必要公开署名，裁去私人聊天与手机界面；能力图注明模型、推理档位、单位和测试范围，不能把单项测试推成整体能力。官方事实、第三方测评与作者想法分清；用户要自己的思考，就安排能读懂的独立表达空间。未核实的断言先查证或收窄，不用“没有出处”等无关字幕替代内容。产品口味等无法从原片确认时缩窄措辞，不凭相似名称推断。语义悬空的字幕先回源；不能听校时，不猜改字，可连同不必要的完整音画段自然删除，避免残留声音与新字幕矛盾。

## 参考与判断

按[exemplars](exemplars.md)选具体片段和源秒数，迁移一种能解决本片问题的做法，先做代表段落正常速度看听，再扩展。只看过画面不能宣称参考音乐踩点已验证。

静音看能否读懂变化；遮住标题是否仍在讲故事；正常速度是否疲于读字、重复或声音与动作分离。真实主体、桌面与操作细节保持清晰；截图口令可稳定停留。技术实现不决定观感优劣。

参考只迁移机制；不把某片句数、字号或换景间隔升为通用模板。
