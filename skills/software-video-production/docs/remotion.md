# 程序化动画与依赖复用

按任务选择工具：Remotion适合语义文字、分层角色、连续小场景与合成，FFmpeg负责源片处理、混音和编码。简单裁切无需引入框架。HyperFrames也可完整渲染，与Remotion选一主渲染，或明确只交换局部叠层；不强制串接。能力/许可边界见[工具工作流](../references/tool-workflow.md)，分镜和软件镜头见[editing](editing.md)。框架本身不能生成真人表演、复杂新姿势或写实镜头。可运行的十二类软件与信息动效见[motion](motion.md)，按关系选择，可换主题，不要求每片凑齐；动画结束后应能稳定阅读。

先查已有Node、Remotion、浏览器、FFmpeg与缓存，复用满足任务的版本。共享运行时用可配置路径，项目保存锁文件和素材索引；不携带作者机器的node_modules。新增大依赖说明用途与下载量级，未授权不自动部署模型或浏览器。

可尝试已有Chromium系浏览器的受支持可执行路径，用独立渲染profile先渲染一帧验证；不能因找到了浏览器就宣布兼容。观看用户登录态与离线渲染使用不同用途的profile，不复制登录资料。

动画由帧号和确定性参数驱动，不依赖Date.now、未固定随机数或实时网络。每段局部时间轴显式隔离（例如Sequence），避免全局帧污染角色和文字入点。图片、字体、音频本地引用，避免逐帧拉取远端。

自研镜头/Remotion入口见[integration](integration.md)，原版选定组件真实调用见[upstream](upstream.md)。来源与验收分别记录，不把选定组件的合成通过说成全卡库或真实素材审美已验证。

先生成代表段落，正常速度验证动作与声音，再扩展。并行解码/截图造成阻塞时减少并发；从最终编码检查首尾、边界帧和真实像素尺寸。重建缓存可清理，源图层、时间轴与锁文件不是缓存。
