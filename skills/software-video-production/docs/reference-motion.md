# 玻璃动效与代码式剪辑

用于参考片拆解、软件展示叠层和剪辑工具选型。需要交代真实操作时，先用真实、已脱敏的屏幕证据，再用动效引导读者看重点。

## 先挑一个值得做的镜头

- 用 OpenMotion 的 Motion.md 思路记录每镜的时间窗、要表达的关系、前后镜共享的对象、字幕/音效落点和可替换素材。例如从列表切到详情，前后保留同一个任务名或状态值，让观众知道镜头追的是同一件事。模板页可能只有参考视频和分镜说明，先核对是否提供可编辑工程及所用素材许可。[OpenMotion](https://github.com/nexu-io/openmotion) · [软件流程案例](https://open-design.ai/templates/an-agent-payment-with-human-approval-motion-design/)
- 从 StyleKit 提取配色、层级、圆角和材质。玻璃可放在一张悬浮信息卡、功能结果提示或短转场。用半透明底、局部背景模糊、细亮边和柔影分层，正文保持清晰不透明。浅背景先安排一块有明暗差的底纹或反射，玻璃轮廓才读得出来。编辑杂志风可提供标题层级及留白。[玻璃拟态](https://www.stylekit.top/zh/guides/glassmorphism) · [液态玻璃](https://www.stylekit.top/zh/styles/liquid-glass) · [编辑杂志风](https://www.stylekit.top/zh/styles/editorial)
- 阿杜导演公开的 .motion 约定把参数、资产和时间驱动页面分开。移植到已有渲染器时，至少把文字、主题色、素材和入场/落定时间做成可替换输入。每次按局部时间独立计算画面，乱序定位同一帧应得到同一结果。若确实走 .motion 宿主，按规范提供 window.film.frame(t) 与所需资源清单，并单独验收导入。[.motion 规范](https://github.com/adunext/adudir-open/blob/main/docs/motion-format.md)
- 首轮取一个代表镜头，和直接切版用同一素材对比。检查入场、交接、落定三处是否看得懂，手机尺寸检查字幕、人物脸、软件操作与动效的遮挡。背景滤镜异常时，用浅色半透明面板、亮边和层次阴影降级。玻璃从合成样片迁到真实口播后，重新检查实际背景、编码和读字停留。

## 什么时候试 MEP

MEP 适合已在兼容剪辑器中建好工程、需要反复按片段 ID 微调时间线的任务。通过宿主读状态、批量提交局部改动、取预览并回读，比逐项点界面更有机会节省往返。现有 EDL/渲染器可直接完成的单次工作，先保留原路线作为对照。磁盘上的 MOV/MP4 需要先导入宿主。阿杜导演是参考实现。演示可先验证基础操作，具体的粗剪、字幕、素材搜寻和其它可选能力以当前宿主的清单为准。[MEP 规范](https://github.com/adunext/mep/blob/main/SPEC.md)

1. 在已授权的独立工程副本中打开宿主协作，读取 README.md、mep.json、status.json、project.json。核对单据与心跳、实际能力、是否计费，以及素材时间和成片时间各自的坐标。口令只用于当前请求，留证时脱敏。
2. 先对现有时间线取 look 预览，再选最小的可逆切点、位置或音量改动。已有逐字信息且宿主支持 roughcut 时，考虑先 read、preview，再决定 apply。每次改动前刷新 revision，用宿主提供的 submit.mjs 或按规范以唯一 ID 提交；等待并核对同 ID 回执、revision 与实际画面。遇 conflict 重读后重算，超时按同 ID 查回执与工程状态，避免重复写入。验收整单撤销及其对后来用户修改的保留。
3. 用同一段粗剪跑现有路线和 MEP 路线，做相同的气口收紧、字幕或音量调整和预览回读。分别记录首次初始化、后续操作与返工耗时、请求/人工次数、任何实扣费用，以及两版的声画和可编辑性。用稳态净节省判断是否采用；只有文档或合成试验时，记录为候选。
4. 协议内预览用来查切点和构图。完整声画仍听实际导出；MEP 规范将最终导出交给宿主中的用户确认。若当前宿主未提供所需能力，继续用已可运行的制作路线。
