# 复盘时重写规则

收尾目标是让下一次更会判断，同时保持读取成本可控；优先压缩、重排和改写，不逐次追加补丁。

## 一次复盘的处理

1. 在项目或对应案例保存用户原话、所指版本、实际改动、结果、检查范围与未知。技术通过、用户采用、封面认可、公开发布和平台表现分别记录。
2. 找到已有模块中负责这一决策的段落。普通制作把改进写成项目内的候选差异，按[运行小结与贡献](run-summary.md)先交付，再评估和邀约；不自动修改安装中的共享skill或提交PR。已有明确skill维护授权时，新证据支持可直接合并改写；冲突时收窄范围或替换旧结论；具体参数、账号或过程留项目。
3. 通读受影响章节，删除被新表述替代的重复规则、旧状态与临时补丁。不能只把臃肿从入口搬到另一个必读文件。
4. 入口只留执行顺序和必要边界；导航只负责定位；案例只作追溯，不要求每次全部加载。检查总读取成本与关键能力是否仍保留，压缩不以删字数本身为目标。
5. 已授权修改skill时检查链接和结构，更新版本与本机共享副本；结构校验与下述行为验收分开记录。普通制作仅保存本次小结和贡献候选。未请求不发布技能、推远端或改其他技能的通用行为。

## 什么进入规则

| 证据性质 | 处理 |
| --- | --- |
| 当次硬约束 | 留项目，当前执行；下次重新核对 |
| 系列偏好 | 在对应决策中注明适用系列和可覆盖性 |
| 已观察结果 | 记录对象、版本、证据与范围，避免全局化 |
| Agent归因/改进想法 | 标记假设，定义下一次如何观察 |

案例采用“问题→选择→反馈/验证→结论与范围→未知”即可。失败、采用和评分属于对应版本；成片评分不能转成封面或留存证明。收到重复负反馈就修正原判断，不能继续堆“必须加角色/特效”的条款。

## 用产物检验规则

用户要求CR或实质改写创作决策时，先做轻量脚本测试，不默认渲染整片。选少量真实任务，包含未在范例出现的新情境，开跑前固定输入、达标条件和版本；执行者只拿任务、skill/doc与必要事实，不给旧结论或标准答案。有授权且可委派时，用独立上下文执行，再让未参与写作的评审看任务和产物。

评具体事件、第一份回报、因果/词义、自然台词、动作与时间密度，以及事实/任务边界，不按是否复述规则或具有规定标题给分。时间表闭合不能证明对白演得完；结构和链接通过也不能证明创作达标。

保留失败脚本与证据，区分规则缺口、执行遗漏和待验证项。只修对应段落，再独立重跑失败题，并补一题未见过的情境检查过拟合；不把改后脚本替换成初次结果。脚本测试只支持脚本层结论，问题涉及动作观感、声音或平台裁切时才升级相应媒体验证；不据此宣布用户认可或留存提升。用例、评分和运行记录留测试项目，不塞进常用入口。

## 锁定、发布与清理

用户采用后锁定成片，未请求不继续剪。发布分别记录Agent保存/回读、提交审核、平台公开与用户确认；用户说已发布可以作为用户确认归档，不伪称独立核验，也不推出审核通过或传播表现。

清理按实际授权范围核对保留文件、哈希和绝对路径。泛称“清理一些工程”优先处理可重建缓存，保留源素材与重建资料；明确只留成片/封面时按该范围执行，不重复询问已授权删除。共享素材和其他项目不在范围内。可恢复归档要说明占用迁移到哪里，不能说永久删除或总存储下降。同步入口的失效链接与重建限制。
