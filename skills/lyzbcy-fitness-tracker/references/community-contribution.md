# 使用小结与集思广益提PR

先完成用户训练收尾，实际交付总结PNG并核对博客结果。简短小结包含：完成了什么、用户指出的问题、怎样修正、真实验证和仍未知的事项。没有反馈/历史就如实写未知，不编迭代次数。

**等用户确认最终交付可用后，才评估是否邀请贡献。** “练完了”只是收尾触发，不等于最终图片已确认；还在返工、博客恢复或图片发送未明时先解决任务，不征集PR。多skill共同完成一次任务时，由最后阶段合并一次小结/邀约，避免重复问。

## 评估与草案

- 值得贡献：可复现的统计口径修复、动作分组边界、长图溢出、表情语义选择、跨平台运行/更新恢复等通用经验。
- 普通训练成绩、个人PR、私人饮食/身体状态、好评或耗时长不自动构成可迁移经验。
- 有价值时先做小型、可审阅的脱敏草案，说明问题/触发条件、拟改文件和最小差异、验证与未知。优先虚构最小复现，不打包整套用户工程。
- 不公开真实训练账本、身体指标、健康/营养数据、照片、聊天原文、身份账号、配置、绝对路径、认证或未授权素材。引用本人原话和真实素材另需明确公开许可。自动扫描不是人工脱敏复核的替代品。

在当前项目准备已人工复核的短文本，然后用随包助手管理本次专属目录：

```bash
python scripts/contribution.py prepare --workspace /当前项目私有目录 --summary /已脱敏的草案.md --patch /最小改动.patch --confirmed
```

`--confirmed`只能在用户确实确认最终交付后使用。助手只读显式指定的短文本，不读取整个workspace或训练JSONL；输出本次run_id、草案位置及“尚未提交”。未确认时不准备、邀请或提交。

## 邀请一次，同意后才提交

> 这次“……问题的……修复”有复用价值。我已整理脱敏草案（链接），准备修改……，验证了……。你愿意将它作为PR贡献给本skill吗？审核合入后，可按你确认的名字或GitHub账号登记贡献者，也可以匿名。目前尚未提交，不贡献不影响交付。

没有真实价值则不机械询问。拒绝或沉默不算同意；不反复劝说，不从用户名/邮箱猜署名。邀请只能发给当前操作者，不向训练群、公众号粉丝或其他联系人发送。

用户同意公开范围后，在其可用fork/贡献分支提交PR，目标`lyzbcy/laoyu-miaomiao-tools`、路径`skills/lyzbcy-fitness-tracker/`。PR描述具体问题、最终行为、合成复现/验证和限制；不要直接推主分支或自动合并。按确认的署名在同一PR更新[CONTRIBUTORS.md](../CONTRIBUTORS.md)，实际合入后才说已成为项目贡献者；匿名只记贡献项，不泄露身份。创建后返回真实链接，并按宿主要求附加到当前聊天。

若没账号、权限或网络，只交付最小补丁/PR正文并说明尚未提交，不借用维护者或其他人的身份。当前用户明确授权维护本skill、直接发布修复时，按已有授权完成，不强制改成贡献PR，也不重复问维护者署名。

## 用户答复后清理

拒绝：记录不提交，清理本次贡献包，停止邀请。

```bash
python scripts/contribution.py answer --workspace /当前项目私有目录 --run-id 本次编号 --decision decline
```

同意：先完成已授权的PR/补丁交付，再记录结果并清理；不能先删唯一补丁。署名默认anonymous，其他值由本人确认。

```bash
python scripts/contribution.py answer --workspace /当前项目私有目录 --run-id 本次编号 --decision accept --result-url https://github.com/lyzbcy/laoyu-miaomiao-tools/pull/实际编号 --credit anonymous
```

提交失败时，将最小补丁另存于项目的正式记录中，再清临时包：`--decision accept --patch-out /当前项目私有目录/contributions/最小补丁.patch`。说明未提交；保留最小文字补丁，不留下大ZIP。未答复时用`--decision pending`不提交、不把沉默当拒绝，不重复造包。

助手只清`.contribution-tmp/<本次run_id>/`内自己登记的草案/补丁；验证路径，不跟随符号链接，不递归删除其他项目，遇到未知文件保留并报告。保留正式交付、原始素材、运行小结、PR链接或最小补丁、贡献结果。答复后的这项清理由组件授权，不再问一次。没有创建包时如实说无需清理。
