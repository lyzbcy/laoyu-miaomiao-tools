# C08 图标资源与接入

适用线索：添加/修改图标、设计切图、图标库已有资源、沿用旧 svg-icon。以下为脱敏重构案例，不是真实对话或具体项目规范全文。

## 识别与决策

按钮的空态用旧 `svg-icon`，有值态另引一张编辑图片。视觉上都能显示，但实现前没有核当前图标库及接入约定，导致同一控件混用资源体系。

编码前分开确定两件事：

1. **资源来自哪里**：当前图标库是否有与设计一致的资源。已有则复用；新设计未入库可直接用设计切图，或请设计补充资源。不能为了“必须入库”阻塞已有明确切图方案。
2. **如何渲染**：查当前组件契约及成熟新实现。若项目已明确不再用旧 svg-icon 接切图，就使用库支持的类名/组件，或按工程约定导入图片；不能凭历史示例决定新实现。

## 修复示例

假设当前库提供下面两个字体图标类名，并且按钮默认插槽支持图标：

```vue
<app-button type="text" :disabled="disabled" @click="openPicker">
  <i :class="hasSelection ? 'icon-lib-edit' : 'icon-lib-add'" aria-hidden="true"></i>
  {{ hasSelection ? '修改' : '添加' }}
</app-button>
```

类名和按钮仅为示例，不能复制到未核对契约的项目。按钮若已有推荐的 icon 属性，优先按它的契约接入。若库中没有对应资源且设计要求使用新切图，可按当前构建工具导入图片并设置合适尺寸与装饰性替代文本，不再转接旧 svg-icon。

## 边界与正常反例

- 不是禁止 SVG 格式，也不是要求全项目移除 svg-icon。其他项目仍以 SVG 组件为正式方案时，按该项目契约使用。
- 不是把所有旧图标一起重构。检查本次修改控件的添加、修改等状态，其他历史问题按归属和任务范围处理。
- 库中同名图标不一定匹配设计，仍要核形状、尺寸、颜色及交互状态；图片资源不应依赖字体颜色自动变色。

## 回归

- 空、有值、禁用状态均正确显示；新增图标的字体文件或图片请求成功。
- 图标与文字基线、尺寸、间距正常，hover/禁用颜色遵循组件契约。
- 点击仍打开原选择器，取消和已有选择的回显不变。
- 用真实页面核渲染效果；能搜到类名或编译成功不能替代实际加载检查。
